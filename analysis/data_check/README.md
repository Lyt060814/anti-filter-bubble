# 数据与可行性检查（写 Plan 之前的准备工作）

> 2026-10-02。目的：在写 Project Plan 之前，把数据、类目对齐、算力和用户模型这几个前提逐一核实。
> 脚本按编号运行：`00_download.sh` → `01`…`06`，每一步的输出在对应的 `.out` 文件中，路径统一写在 `common.py`。
> 数据放在仓库外的 `/home/user/data`，不提交。**本目录下的脚本都没有调用任何 LLM。**

## 0. 一句话结论

1. **ShortVideo（清华 FIB，WWW'25）可以用，但公开的只是抽样版**：6,654 个用户，129k 条交互，31k 个视频，只有一周数据，每个用户的交互数中位数是 10。而且记录**不是连续的刷视频过程**（同一用户相邻两条记录的间隔中位数是 819 秒）。所以它适合做内容池、用户画像和 LLM 对照实验，**不适合**训练序列模型或校准仿真动态。
2. **三个快手数据集共用同一套一级类目 ID**。中间改过几次名、拆分过、合并过，还有一个 ID 被挪作他用，已整理成 34 个三方共有的统一类目（`category_map_l1.csv`）。二、三级类目只有部分重合，**跨数据集比较只用一级类目**。
3. **KuaiRand 作者在 2026-01 补发了官方的视频标题和类目文件**（Zenodo 18159199，CC BY 4.0）。KuaiRand-1K 日志里涉及的 437 万个视频 100% 能对上，82.5% 有标题。这样 KuaiRand 也有了文本，可以算内容向量。
4. **许可证更正**：KuaiRec（Zenodo 18164998）和 KuaiRand（10439422）的官方记录**都是 CC BY 4.0**。Plan 里写的 "CC BY-SA 4.0" 来自第三方镜像，要改。ShortVideo 没有写明数据许可证，按作者的研究用途条款使用，不再分发原始视频。
5. **算力够用**：中文标题向量化在 4 核 CPU 上约 515 条/秒，向量能反映类目结构。一个 Phoenix 风格的小排序模型（L1）在 CPU 上跑完 KuaiRand-1K 一个 epoch 约需 15–20 分钟。**不需要 GPU。**
6. **逃离有数据依据**（KuaiRand 随机曝光日志）：对于用户历史里排第 4–10 名、第 10 名以后的类目，长播率分别还有第一兴趣类目的 77% 和 52%。用户之间差异很大：茧房外与茧房内接受度之比的四分位数是 0.43 / 0.91 / 1.37。
7. **"LLM 是否比参数化模型更像真人"可以直接测**：已搭好测试集（977 个用户，13.5k 条曝光）。非 LLM 基线在单个用户内部预测"是否划走"的 GAUC 只有约 0.54，分数线很低，这个实验能给出明确的答案。

## 1. ShortVideo 抽样版（`01`）

| 项目 | 抽样版（公开） | 论文中的全量（未公开） |
|---|---|---|
| 用户 / 视频 / 交互 | 6,654 / 31,496 / 129,483 | 10,000 / 153,561 / 1,019,568 |
| 时间 | 2022-09-16 至 09-22（7 天） | 6 个月中的第一周 |
| 每个用户的交互数 | 中位数 10，P75 25，P90 48；≥30 条的有 1,343 人 | — |
| 每个用户每天 | 中位数 3 条，相邻记录间隔中位数 819 秒 | — |

- **CSV 格式**：每一行是"交互 × 标签 × 类目路径上的一个节点"，所以要先按 (user, pid, exposed_time) 去重。我们最初只取第一行，误以为只有一级类目，其实一、二、三级类目都在。
- **`click` 字段**（README 里没有说明）：click=False 时观看时长中位数是 3 秒，click=True 时是 32 秒。实际含义约等于**"没有很快划走"**，可以当作真实的负样本。README 提到的 `effective_view` 在抽样版里不存在。
- **动作稀少**：点赞 2.0%，关注 0.46%，收藏 0.55%，hate（≈不感兴趣）只有 **87 次（49 个用户）**，不能用来校准"不感兴趣"的行为。
- **独有的价值**：真实的人口学信息（年龄均值 47.5，偏中老年；四、五线城市居多）、可读的标题和标签、作者粉丝数（34% 的视频作者粉丝 ≤5 万，即符合 X 冷启动的门槛）、15.3 万个视频的 ASR 文本（服务器上全量都有）。
- **Dropbox 上的"推荐处理版"**：9,609 个用户，29.4 万条交互，但**只有正反馈**（rating 全是 5，没有动作类型）。另外附带全部 153,561 个视频的 50 维文本特征。用处不大。

## 2. 类目对齐（`02`，输出 `category_map_l1.csv`）

- **KuaiRand 补充文件**：用 `final_video_id` 和 KuaiRand-1K 的 `video_id` 对接，时长 100% 一致（347.8 万个两边都有时长的视频），说明连接键是对的。补充文件里的类目是**模型预测**出来的（一级类目置信度中位数 0.986），覆盖率：一级 98.4%，二级 73.7%，三级 33.4%。KuaiRand 原有的 `tag` 字段与补充文件的一级 ID 有 72% 一致。
- **不看名字的验证**：按一级 ID 计算视频时长中位数，ShortVideo 和 KuaiRand `tag` 在 36 个 ID 上的 Spearman 相关是 0.87（置换检验 p < 0.0005）。
- **版本差异与统一规则**（逐个读过视频标题确认）：

| ID | KuaiRand / KuaiRec | ShortVideo | 处理 |
|---|---|---|---|
| 5, 9, 15, 17, 21, 28, 34 | 时尚、喜剧、艺术、宠物、人文、民生资讯、其他 | 穿搭、搞笑、才艺、动物、历史、资讯、随手拍 | 只是改名，ID 不变 |
| 29 / 30 | 科学与法律 | 拆成 29 科学和 30 法律 | 合并为 29 |
| 32 / 39 | 短剧、影视综 | 合并成 39 影视和短剧 | 合并为 39 |
| **23** | **时政资讯**（国际/国内时政） | **宗教**（菩萨、佛法） | **ID 被挪用**：KuaiRand/KuaiRec 的 23 并入 28 资讯；ShortVideo 的 23 单独成组 |
| 33 自拍 / 31 健身 | 有 | 没有 | 33 并入 34，31 并入 7 运动 |

结果：34 个统一类目三方共有，ShortVideo 另有 1 个独有的"宗教"组。二级 ID 中 ShortVideo 与 KuaiRand 共有 85 个，三级共有 131 个，所以细粒度类目只适合在单个数据集内部使用。

## 3. 内容向量（`03`）

`BAAI/bge-small-zh-v1.5`（2400 万参数，MIT 许可证），输入是标题加标签：
- 速度：31,496 条用时 61 秒，约 515 条/秒（4 核 CPU）。KuaiRec 约需 20 秒；KuaiRand-1K 的 437 万个视频约需 2.4 小时，也可以只算实际要用的子集。
- 质量：同类目视频对的平均余弦相似度 0.408，跨类目 0.337；**最近邻视频与自己同属一个一级类目的比例是 0.626，随机水平只有 0.061**。可以用来实现 DPP 的相似度核和"相似内容"假设（H2）。

## 4. 算力（`04`）

Phoenix 风格的小排序模型：输入是用户历史序列（视频 + 类目 + 动作），候选视频之间相互隔离（candidate isolation），输出 7 个动作头。

| 配置 | 参数量 | CPU 速度 | KuaiRand-1K 一个 epoch |
|---|---|---|---|
| 2 层，d=64，历史长度 128 | 12.9M | 约 13k 个候选/秒 | 约 15 分钟 |
| 4 层 | 13.0M | 约 9.8k 个候选/秒 | 约 20 分钟 |

真实的 Phoenix nano 版本需要 A100 级别的 GPU，所以我们的路线是 L1 替代模型，学生笔记本电脑就能训练。

## 5. 用户会不会接受茧房外的内容（`05`，逃离校准的关键）

先用 KuaiRand-1K 前 14 天的推荐日志得到每个用户的类目画像（983 人，每人历史中位数 3,489 条），再看同一时段**随机曝光日志**里的反应：

| 视频所属类目在用户画像中的排名 | 曝光占比 | 点击率 | 长播率 | 相对第 1 名 |
|---|---|---|---|---|
| 第 1 名 | 9% | 0.240 | 0.120 | 1.00 |
| 第 2–3 名 | 13% | 0.236 | 0.125 | 1.04 |
| 第 4–10 名 | 26% | 0.187 | 0.092 | 0.77 |
| 第 10 名以后 | 49% | 0.133 | 0.062 | **0.52** |
| 从没看过的类目 | 3% | 0.260 | 0.083 | 0.70 |

- **结论 1**：用户对茧房外内容的兴趣会下降，但不是零。逃离不是"必然失败"，代价可以量化。
- **结论 2**：即使在第一兴趣类目里，推荐的视频长播率也是随机视频的 2.4 倍（0.29 对 0.12）。**类目内部的匹配**比类目本身影响更大，所以用户模型不能只看类目，需要内容向量或物品层面的偏好。
- **结论 3**：用户差异很大（茧房外与茧房内长播率之比的四分位数是 0.43 / 0.91 / 1.37，样本是 520 名两类曝光各有 ≥5 条的用户）。可以据此定义"易进茧房"和"爱探索"两类用户，作为造茧房用户的依据之一。
- 随机日志里 hate 只有 35 次，同样太少。"不感兴趣"的效果只能按 X 代码里的权重建模，并在报告中明确说这是假设。

## 6. LLM 用户 vs 参数化用户的测试集（`06`）

- **任务**：用 ShortVideo 用户 09-16 到 09-20 的记录，预测 09-21、09-22 每条曝光是否被点开（没有划走）。977 个用户，训练 46.7k 条，测试 13.5k 条，正例率 0.569，测试视频中有 36% 在训练期没出现过。测试集的键存在数据目录下，不进仓库。
- **非 LLM 基线**：

| 模型 | 整体 AUC | 用户内 GAUC |
|---|---|---|
| B0 只用该用户的点开率 | 0.687 | 0.500 |
| B1 加上用户×类目偏好 | 0.660 | 0.542 |
| B2 再加时长、作者粉丝数、时段 | 0.661 | 0.542 |
| B3 再加标题向量相似度 | 0.665 | 0.540 |
| B4 梯度提升，全部特征 | 0.662 | 0.539 |

- **解读**："这个用户整体爱不爱点"很好预测，但"这个用户会点哪一条"几乎预测不了（GAUC ≈ 0.54）。LLM 可以读懂标题、结合人口学信息推理，如果它能明显超过 0.54，就说明它值得用作用户模型；如果超不过，说明 LLM 的"偏好"和真人对不上，或者这个任务本身噪声太大，两种情况都要如实报告。
- **成本粗估**：每个用户一次调用（画像 + 约 50 条历史标题 + 约 14 条测试标题），约 2k token，共约 200 万 token。**需要组内自己准备 API key**，本次没有调用任何 LLM。

## 7. 还没核实的事项

- ShortVideo 的全量数据是否可以向作者申请；抽样方式（按用户还是按交互抽样）也不清楚，会影响画像的代表性。
- ShortVideo 原始视频约 3.6 MB 一个，如果要做"给 LLM 看视频画面"的多模态实验，只能取几千个视频的子集。
- KuaiRand 补充文件里的类目是模型预测的，存在误差（`tag` 与它只有 72% 一致）。
