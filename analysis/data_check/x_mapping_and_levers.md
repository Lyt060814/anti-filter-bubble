# X 动作头与快手动作的对应关系，以及用户侧"逃离"操作的生效机制

> 2026-10-02。代码依据：xai-org/x-algorithm 提交 `b79b947`（本地克隆）和 `docs/resources/x_algorithm_code_map.md`。
> 标注：[V] 代码已核实，[I] 推断，[U] 仓库里没有，无法核实。

## 1. 价值模型的动作头 ↔ KuaiRand / ShortVideo 字段

X 的打分是 `S = Σ w_a · P̂_a`。**缺失的预测按 0 处理**（`xai-value-model/scoring.rs:57-59` [V]），所以对没有数据的动作头，"保留权重、预测设为 0"本身就是 X 的做法，不需要我们另造规则。

| X 动作头 | 权重 | KuaiRand 字段 | ShortVideo 字段 | 对应程度 |
|---|---|---|---|---|
| favorite（点赞） | 0.5 | `is_like` | `cvm_like` | 好 |
| reply（评论） | 5.0 | `is_comment` | `comment` | 好 |
| 互关作者的评论加成 | +15.0 | 无（只有好友数，没有用户之间的关系） | 无 | **缺失** |
| retweet（转推） | 1.0 | `is_forward`（二选一） | `forward` | **有歧义** |
| share / 私信分享 / 复制链接 | 2.0 / 5.0 / **20.0** | `is_forward`（只有一个字段） | `forward` | **有歧义**：X 分成三种，权重差 10 倍 |
| quote（引用） | 5.0 | 无 | 无 | 缺失（X 独有） |
| click / video open | 0.3 / 0.07 | `is_click` | `click`（≈没有划走） | 近似 |
| dwell（二值） | 0.05 | `long_view` | `watch_time` > 阈值 | 近似 |
| 连续停留时长 / 点击后的停留时长 | 0.004 / **0.4** | `play_time_ms` | `watch_time` | **单位不确定**（见下文） |
| follow author（关注作者） | 4.0 | `is_follow` | `follow` | 好 |
| profile click | 0.0 | `is_profile_enter` | 无 | 权重为 0 |
| photo expand、open link、quoted click、PostUnexplored | 0.05 / 0.2 / 0.05 / 0.02 | 无 | 无 | 缺失，权重很小 |
| **not interested（不感兴趣）** | **−47.52** | `is_hate`（共 2,129 次，很稀少） | `hate`（87 次） | 好，但数据稀少 |
| block / mute author（拉黑 / 静音作者） | −31.2 / −58.8 | 无 | 无 | 缺失，但在仿真里它们是**用户可以选择的操作**（硬过滤，见第 2 节） |
| report（举报） | −234.0 | 无 | 无 | 缺失 |
| not dwelled（没停留） | −0.02 | 1 − `long_view` / 很快划走 | `click` = False | 近似 |

**按权重计算的覆盖率**（正向权重之和 PosSum = 43.24，`weights.rs:45-63` [V]，不含互关加成和连续时长项）：能对应上的有点赞 0.5、评论 5、转发按 share 计 2、click 0.3、video open 0.07、dwell 0.05、关注 4，合计 **11.92，约占 28%**。没对应上的主要是复制链接 20、私信分享 5、引用 5。

但权重乘以概率才是贡献。这几类动作在 X 上的基础发生率不公开（代码注释说举报的基础概率比点赞低 1000 倍以上，`param.rs:273-301` [V]），所以**实际贡献占比无法计算**。

**连续停留时长的单位** [V + U]：
- Phoenix 的连续头按 `gt / norm_scale` 归一化训练，所以模型原始输出在 0–1 之间（`loss_recsys.py:65-71`）。
- 只有激活函数为 `sigmoid` 的头会在推理时乘回 `norm_scale`，变成秒（`recsys_model.py:294-311`）。默认激活函数是 `None`。
- 仓库里只有 DWELL_TIME 头的配置（`norm_scale` 为 30 秒）；**click-dwell 头的生产配置不在仓库里** [U]。
- 由此有两种可能：
  - 输出是 0–1 的值，0.4 × 约 0.3 ≈ 0.1，与 click 那一项（0.3 × P(click)）同量级；
  - 输出单位是秒（0–60），0.4 × 10 秒 = 4，会主导所有正向项。
- 另外，连续时长项**不计入** PosSum/NegSum，不参与负分的压缩处理（`weights.rs:45-76` [V]）。

**对仿真的建议**：
1. 保留 X 的全部权重；能用快手数据预测的动作头照常预测，其余设为 0，与 X 处理缺失预测的方式一致。
2. 把三个分歧点做成敏感性参数：转发对应哪种权重（1 / 2 / 5 / 20）、连续停留时长的单位（归一化值还是秒）、互关加成（关或开，开的话需要模拟关注关系）。
3. 在报告里说明："不感兴趣"的效果只能按 X 的权重建模；快手数据里点"不感兴趣"的次数太少，无法校准用户会多频繁地使用它。

## 2. 用户侧操作：在 X 的 For You 流程里如何生效

| 用户操作 | 生效方式 | 持续多久 | 对茧房的作用 | 能否在仿真里实现 |
|---|---|---|---|---|
| **不感兴趣 / 少看这类** | **不是硬过滤** [V]。只通过模型生效：(1) 预测 P(不感兴趣) 乘以 −47.52；(2) 可能作为历史输入，但生产环境的聚合方式 `DENSE_WITH_LONG_DWELL` 可能把它排除了 [I/U]；(3) 作为召回模型训练时的负样本 | 元数据里的 TTL 是 30 天，但执行逻辑不在仓库里 [U]；对模型的影响持续到这条记录被 1024 条的历史窗口挤出 | 让模型学会少推，但效果没有保证 | 可以。三种作用范围（A/B/C）已在 `sim.py` 里实现 |
| 话题层面的"不感兴趣" | 只有在 `EnableTopicFeedbackContext` 打开时才附带话题标签，而它**默认关闭** [V] | 同上 | 实际几乎无效 | 可以作为一种"无效策略"对照 |
| **静音 / 拉黑作者** | **硬过滤** `AuthorSocialgraphFilter` [V] | 直到用户撤销，代码里没有 TTL | 只能去掉某个作者，**不能**去掉一个话题。同话题的其他作者照样会推 | 可以 |
| **屏蔽关键词** | **硬过滤** `ViewerMutedKeywordFilter`（对帖子文本分词后匹配）[V] | 只要关键词还在列表里 | 能按文字去掉一个话题。**最接近"直接关掉某个话题"的操作** | 可以，但需要标题文本（ShortVideo 和 KuaiRand 都有） |
| **主动和其他内容互动**（点赞、长看、评论） | 改变最近 1024 条历史 → 同时影响 Phoenix 召回（最近邻）、SimClusters 种子（每类动作最近 15 条）和排序 [V] | 先进先出窗口，越活跃的用户被挤出得越快 | 主要的"拓宽"手段 | 可以，这是核心策略 |
| **关注新作者** | Thunder 站内召回（按时间排序，最多 1200 条）；站外内容有 ×0.75 的折扣，所以关注的作者天然更占优 [V] | 直到取关 | 通过关注关系拓宽，站外折扣让它更有效 | 可以，但需要模拟关注关系（快手数据里没有） |
| 多刷新几次 | 已看过 / 已推送过的帖子会被过滤（推送记录保留 10 分钟或 100 条）[V] | — | 只保证不重复同一条，**不保证话题会变** | 可以 |
| 平台侧：冷启动探索 | Thompson sampling，每次请求最多 1 条，抬升到第 15 位 [V] | — | 小幅拓宽，用户无法控制 | 可以，作为仿真背景机制 |
| 搜索、探索页、话题页 | 不在 For You 流程里；话题请求的站外折扣是 ×0.5 [V] | — | 间接影响：在那里的互动会进入历史 | 可以简化为"注入 k 条外部互动"；建议列为局限 |

**要点**：
1. 用户手里**唯一能按话题硬性关掉内容的是屏蔽关键词**，"不感兴趣"是软的，静音只针对作者。这应该成为逃离实验的一个核心对比：软操作对硬操作。
2. 话题层面的"不感兴趣"默认没有接通。这本身就是一个值得写进报告的发现。
3. 历史窗口按条数计，不按时间：越活跃的用户越容易逃离，也越容易复发。这与检测部分发现"活跃度信号很强"是一致的。
