# 数据与源码实物检查

2026-10-02。这是资源可用性和原计划主张的核查，不是按钮效果实验，也未生成自动立场标签。资料根目录为仓库同级 `anti-filter-bubble-sources/`。计数均注明原始/过滤/去重口径；更完整的来源和访问限制见[来源台账](plan_source_review.md)。

## 1. 已恢复的数据及其单位

### KuaiRand

从官方 Zenodo 下载并解压 1K 和 Pure；1K 原始三份日志实读结果：

| 日志 | 行数 | 用户 | is_hate | is_follow |
|---|---:|---:|---:|---:|
| standard 04-08—04-21 | 5,055,984 | 983 | 8,727 | 5,722 |
| standard 04-22—05-08 | 6,657,061 | 1,000 | 2,129 | 5,676 |
| random 04-22—05-08 | 43,028 | 1,000 | 35 | 8 |

标准日志合计 **11,713,045** 行、10,856 次 hate、11,398 次 follow；含随机曝光合计 **11,756,073** 行、4,371,868 个不同视频。至少发生过 hate/follow 的用户分别为 274/831 人。入口包含多个 tab，标准日志并非每一行都来自同一种单列推荐流。随机数据也有少量非 tab=1 记录。

旧 `analysis/data_check/05_offinterest_acceptance.py` 在计数前执行类目映射和 `dropna(subset=['g'])`。完整补充文件下载后实际复算确认：42,963 是**成功映射到统一类目后的随机曝光数量**；10,713 是**同样映射后标准日志中的 hate 数量**。但计划中的 follow 11,398 来自映射前，映射后是 11,322。v1 混合了两种样本口径，不是所有字段都来自同一筛选后总体。

| 口径 | 标准曝光 | hate | follow | 随机曝光 |
|---|---:|---:|---:|---:|
| 原始 | 11,713,045 | 10,856 | 11,398 | 43,028 |
| 可映射到旧统一类目 | 11,598,236 | 10,713 | 11,322 | 42,963 |

补充标题/类别两文件共约 6.91 GB，均通过官方 MD5 核验。4,371,868 个日志视频在两文件中 **100% 找到 ID**；其中 3,605,249 个有非空 caption（82.46%），结合封面文字后有文本的为 3,750,835 个（85.79%）。按标准曝光加权，非空 caption 覆盖为 87.94%，随机曝光则为 98.94%。因此“82.5% 有标题”是视频口径，不能当作所有分析样本一致的缺失率。

随机池由 7,583 个筛选过的视频构成，而且是插入正常推荐列表。它适合研究该池下的接受度；不是完全非个性化的独立信息流、全平台供给或现实社会观点比例。

可复现检查脚本：[probe_resources.py](../../analysis/context_audit/probe_resources.py)。它读取 2026 补充标题/类目，检查 ID 对齐、非空标题、清洗后事件数量，以及 200 次标准曝光窗口中关键词候选的密度。脚本只做关键词候选统计，**没有把关键词当成立场标签**。

实际得到 **58,066 个完整的、不重叠的 200 条标准曝光窗口**。以下数量按脚本的明确关键词，在 caption + 封面文字中匹配；所有入口都保留，末尾不足 200 条的窗口丢弃。

| 检索入口 | 候选视频 | 标准日志候选曝光 | 候选 ≥20 的窗口 | 至少有一个这类窗口的用户 |
|---|---:|---:|---:|---:|
| 宽婚恋词组 | 62,961 | 212,315 | 149 | 64 |
| 宽育儿词组 | 85,663 | 292,075 | 363 | 78 |
| 宽健康词组 | 23,561 | 61,973 | 44 | 15 |
| 彩礼 | 2,729 | 7,927 | 1 | 1 |
| 鸡娃/快乐教育/严管/棍棒/打骂孩子 | 125 | 372 | 0 | 0 |
| 糖尿病/降血糖 | 702 | 1,499 | 0 | 0 |

这对 v1 是实质约束：**全局有数万条话题内容，不意味着每个人的短窗口都有足够的同命题样本。** 样例阅读还发现，“孩子”会命中宠物、食谱与电视剧，“鸡娃”会命中斗鸡养殖，“严管”会命中交通管制；彩礼材料也包含广告、个人婚礼记录、剧情和没有答案的提问。候选并不等于可判定立场，且检索也会漏掉不用这些词的表达。不能从本表推断全库真实观点数量；可以据此判断**当前关键词路线和 200 条窗口不足以兑现 1,000 人观点评分的产量承诺**。更宽召回、更长观察期或换数据源，都需要重新检验覆盖和任务含义。

完整统计已嵌入[资源清单](resource_manifest.json)的 `probes`；72 条定性样例保存在外部目录 `data/audit/keyword_examples.json`，未作为随机金标准。

### KuaiRec

从官方记录下载 `KuaiRec.zip`，实际解压为 `KuaiRec 2.0`，并取得补充标题、原始类目和用户特征。

小矩阵实读：**4,676,570** 个不同用户—视频对，1,411 用户×3,327 视频，密度 **0.9962024942**。原始 watch_ratio 中位数约 0.769，最大约 571.52；大于 2 的记录 217,175 条。

补充 `kuairec_caption_category.csv` 还存在解析注意点：本机 pandas 默认 C parser 报错；按旧脚本使用 Python parser，得到 10,732 行，其中 10,728 行有数值 video_id，覆盖 0—10,727，其余 4 行不能当视频记录。应显式做 ID、列类型和类别范围检查，不能静默假定任意 CSV reader 都给出相同有效数据。

论文说明：先挑选接近稠密的子集，再用约 15 天补曝光；作者承认流行度偏差；个别阻止作者的用户导致密度未到 100%。论文把累计观看比率大于 2 作为强偏好代理，没有独立测到“我认可自己继续喜欢这个观点”。因此它可提供**有限池内较完整的行为反应**，不能称“真实兴趣的唯一严格来源”。其长尾观看比率也说明，直接线性当福利值不合适。

### ShortVideo_dataset

实际下载作者服务器 `interaction_sampled.csv`、`categories_cn_en.csv`，以及按三个大话题关键词、固定 seed=1110 选取的 **24 份 ASR**。没有下载全量视频和全部 ASR。

| 项目 | 实读结果 |
|---|---:|
| 原始 CSV 行数 | 794,053 |
| 按 `(user_id, pid, exposed_time)` 折叠的曝光 | 129,483 |
| 用户 / 视频 | 6,654 / 31,496 |
| 每人曝光 Q1 / 中位数 / Q3 | 4 / 10 / 25 |
| 相邻可见曝光时间间隔中位数 | 819 秒 |
| 原始 hate 行 / 去重 hate 事件 / 涉及用户 | 431 / 87 / 49 |

原始一条曝光随多级类别/标签出现多行。去重需要保留标签集合，而不是只拿第一行当唯一类目。它不能作为完整连续 feed：每人十来条、间隔十几分钟的抽样记录，无法直接支撑“前后 200 条真实刷屏”分析。

本次候选检索：婚恋 287 视频/1,656 曝光；育儿 454/2,040；健康 29/101。关键词见 `probe_resources.py` 的前三组；这一组关键词与旧分析不同，**不应拿它和原计划的 496/114 直接当数据丢失或增长**。

真实文本带来的测量提醒：

- `pid=62969` 标题含“中医”，ASR 实际在讲游戏组合；关键词会误收。
- `pid=7614` 标题问育儿嫂是否承担全部责任，ASR 给出的是法律职责和条件分析；不能单看问句生成一个支持/反对标签。
- `pid=36998` 的糖尿病标题较强，ASR 中仍出现长期效果待观察的限定；标题可能省略证据条件。
- 婚姻、夫妻争吵内容中混有剧情与人物对白；“角色说了什么”与“作者主张什么”不同。

这些是读取样例后发现的风险，不是随机金标准的误差率。ASR 也可能有错、漏画面、漏语气；必要时应回看视频，或标记无法判断。

### 跨数据集类别并非直接相等

读取三个来源的类目名称，并回看 `02_category_alignment.py` 后确认：ID 23 在 KuaiRand/KuaiRec 是“时政资讯”，在 ShortVideo 是“宗教”；“科学与法律”也被拆分，影视/短剧有合并。原仓库的 34 类映射是**带重命名、合并和剔除规则的协调结果**，不是原始 ID 天然同义。补充类别又是模型预测，带置信度；不能一边把它当无误差真值，一边只给立场标注报告噪声。

克隆位于 `../anti-filter-bubble-sources/code/x-algorithm`，固定提交 **b79b947ce9283c786822274ef8fe208c33c585b2**。以下是源码中的路径、规则与默认值，不是对 X 当前真实账号的产品测试。

## 3. 由实物检查改变的执行判断

1. 原始计数、类目映射后计数、时间窗口够长后的事件数必须分别报告；读取成功不等于同一分析样本。
2. 先看**同一命题**在用户窗口内有多少可判定内容，再确定是否能做个人分数。关键词会误收和漏收；候选密度不是真实观点样本密度，也不是对全数据相关内容数量的严格上界。
3. 标题/ASR/画面条件决定可判定性，不能提前承诺“只有标题也不影响主结论”。
4. 类目、作者、来源和观点是不同变化轴；按钮可能沿其中一个轴生效，沿另一个轴保留。
5. 不需要将所有备用数据全量下载；1K、KuaiRec、ShortVideo 及中文立场基准已足以发现主要可测性问题。27K 扩容只有在事件样本不足且方法成立后才有意义。
