### 4. 自采数据与问卷

- **个人数据导出**：
  - YouTube Takeout：观看记录带时间戳，但没有类别，需要调 API 补；
  - X 数据归档：`personalization.js` 里有平台推断出的兴趣；
  - Instagram：有"Your topics"；
  - B 站：只能用自己的登录会话拉取，约 1,000 条 / 3 个月；
  - Spotify：扩展收听记录；
  - 抖音、微博：App 内"个人信息下载"。
- **自采流程**：每天截图自己的推荐流 → PaddleOCR（中文识别强）→ 用 LLM 给标题打主题标签（先用约 100 条人工标注校验准确率）→ 计算多样性分数。
- **成熟量表**：
  - AMCA 算法意识量表（13 题）；
  - 算法素养量表（22 题）；
  - Bergen 社交媒体成瘾量表（6 题，有中文版）；
  - 渠润泽 & 徐敬宏（2026）的信息茧房量表（需要通过 HKU 图书馆拿到原题）。
- **伦理（重要）**：
  - HKU 规定，本科生主导的、涉及人类参与者的研究需要伦理审批，通常要 3 周。**问卷和访谈必须先问课程协调人**。
  - 小红书禁止爬虫，也会惩罚批量注册的账号（已有人因爬取小红书数据被判刑）。
  - X 的条款禁止爬取。
  - **只用我们自己的账号和数据、人工操作、不爬取**，是最稳妥的路线。

### 5. 解决方案侧的关键证据

- **多样性不一定损害用户参与度**：YouTube 的 DPP、Google 的探索研究、Prosocial Ranking Challenge 都提示这一点。
- **单纯增加多样性曝光，目前没有证据能改变人的态度**（Nyhan 2023、Guess 2023）。
  → 更稳妥的成功标准是"曝光多样性"和"用户控制感"，而不是"态度改变"。
- **茧房一旦形成可能不会自然消退**：2026 年 *Nature* 上一项关于 X 的研究发现，打开算法会改变观点，但关掉算法后观点不会恢复。
  → "预防"可能比"事后重置"更重要。
- **现有的用户控制普遍很弱**（Mozilla 2022；Kaplan 2026）。

## 二、X 算法代码：已核实的关键事实

以下由我们直接读代码确认（✅）。完整分析见 `x_algorithm_code_map.md`。

| 机制 | 位置 | 参数 | 对多样性的作用 |
|---|---|---|---|
| 打分 = Σ 权重 × 预测互动概率 | `home-mixer/params/param.rs`、`xai-value-model/scoring.rs` | 点赞 0.5、回复 5、引用 5、关注 4 | 按互动优化，是反馈循环的来源 → **收窄** |
| 负反馈权重 | `param.rs:384-407` | 不感兴趣 **−43.2**，拉黑 −31.2，静音 −58.8，举报 −234 | 乘的是**预测的**概率，不是硬过滤 → 效果间接 |
| 作者多样性衰减 | `vm-ranker/params.rs:139-156` | 开启；衰减 0.5，下限 0.25 | 同一作者的帖子逐条降权 → **拓宽** |
| 未关注账号折扣 | `vm-ranker/params.rs:175-180` | ×0.75（话题请求 ×0.5） | 偏向已关注的内容 → **收窄** |
| DPP 多样性重排 | `vm-ranker/dpp.rs` | 配置里是开启、θ = 0.65、前 150 条；命令行默认是关闭、θ = 0.5、前 100 条 | 内容相似的帖子被挤掉 → **拓宽**（线上是否启用无法从仓库确定） |

> ⚠️ **更正**：我之前说"作者多样性似乎被写死关闭"，这是**错的**。`home-mixer/scorers/value_model.rs` 里的关闭设置只用于备用打分路径；正常情况下由 vm-ranker 重新打分，作者多样性是**开启**的。

其他要点（来自代码地图，🔎 待复核）：
- "不感兴趣"类反馈在仓库里**没有任何硬过滤**，只通过模型起作用；"对这个话题不感兴趣"选项默认关闭。
- 模型输入只有用户最近 ≤1,024 次行为，是按**行为次数**计的"记忆"，不是按时间。
- 候选内容是逐条独立打分的，模型本身看不到整个推荐流是否单一。
- 仓库自带 `ResponseDiversityStats` 多样性统计：作者 HHI、熵、语义 ID 熵、已关注账号占比。这是一套**现成的指标定义**。
- Phoenix 模型需要 A100/H100 级 GPU，免费 Colab 基本跑不了。但 `world.py` 可以用来生成合成用户。

## 三、第一个真实数据点：KuaiRec 快速查看 ✅

脚本：`analysis/kuairec_quicklook.py`。每个"用户-周"计算一级类别的归一化 Shannon 熵（1 = 完全分散，0 = 只看一类）：

| 周 | 被展示内容的熵 | 深度观看内容的熵（watch_ratio ≥ 2） |
|---|---|---|
| 0 | 0.764 | 0.535 |
| 1 | 0.662 | 0.289 |
| 3 | 0.752 | 0.382 |
| 4 | 0.799 | 0.578 |
| 5 | 0.765 | 0.424 |
| 7 | 0.754 | 0.408 |
| 8 | 0.770 | 0.491 |

初步观察（仅供讨论，**不是结论**）：
- 两个月内"被展示"的多样性**没有明显下降**；
- "深度观看"的多样性**一直显著低于**被展示的多样性。这和文献中"用户自己的选择比算法更收窄"的发现一致。
- 局限：
  - 熵的大小受每周条目数影响；
  - 第 2、6 周没有数据；
  - "深度观看"只是一个粗略代理；
  - 数据来自 2020 年的快手。
