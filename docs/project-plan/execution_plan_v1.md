## 0. 理想与实际的偏差一览

| 理想中想做的 | 实际能做的 | 损失了什么 | 怎么诚实处理 |
|---|---|---|---|
| 在抖音/快手的真实算法上做可控实验 | 三方互证：X 公开代码（机制）+ 快手 2022 真实日志（结果）+ 按 X 机制构建、用快手数据校准的仿真（代价） | 没有任何单一证据同时具备"真实平台 + 可控" | 每个结论标注证据来源和等级 |
| "关闭个性化推荐"作为每个人的反事实参照 | 仿真里直接关掉个性化；真实数据里用 KuaiRand 随机曝光（来自 7,583 条精选池，占 0.37%）近似；真实平台只做组员自我审计案例 | 随机池不等于全库，不是真正的"关闭个性化" | 写明随机池的局限；自我审计只作案例 |
| 每个用户自述的"认可标准" | 只有组员和愿意参加的同学（20–40 人）的自述；对 KuaiRand 的 1,000 个匿名用户只能用"自身早期分布"和"群体分布"代替 | 匿名日志用户没有自述 | 两种参照分开报告，不混用 |
| 观点维度覆盖所有议题 | 固定 3 个日常议题：两性/婚恋、育儿/教育、养生/健康（数据密度最高、两边都有人发） | 不覆盖政治等敏感议题，也不覆盖低密度议题 | 作为范围限定写明 |
| 立场标签是真值 | LLM 初标 + 300 条人工双标核验；中文零样本立场识别的已知上限约 F1 0.64 | 标签有噪声 | 报告 κ 与混淆矩阵，并在分布层面做噪声校正，给区间 |
| 真实用户的逃离与复发 | 仿真给出区间；KuaiRand 事件研究给出真实平台上按钮的"结果层面"效应；TikTok/YouTube 文献给复发的真实先例 | 没有自己在真实平台上测复发 | 跨平台对照表，明确哪格是别人的、哪格是我们的 |
| 多模态理解视频 | 只用标题、话题标签、类目（KuaiRand 官方补充文件 82.5% 有标题；ShortVideo 有标题和 ASR） | 画面信息缺失 | 列为局限；不影响三个问题的主结论 |

## 2. 工作包

### WP0 定义冻结（第 1 周，全员）
**做什么**
1. 主题维度：沿用 34 类统一一级类目。
2. 观点维度：冻结 3 个议题及其"命题"。候选命题（每个议题 1–2 条，必须是能站两边的）：
   - 两性/婚恋：彩礼该不该要；婚姻中谁该让步/女性该不该"独立"叙事；
   - 育儿/教育：该不该严管、鸡娃 vs 快乐教育；
   - 养生/健康：某类养生说法（食疗、中医偏方）有效 vs 质疑/辟谣。
   第一周用关键词从 KuaiRand 标题里各抽 200 条人工看，确认两边都有，再定命题。
3. 标签规范（借组员路线图）：主题 → 议题 → 是否表态 → 立场（支持/反对/有条件/混合）；"无观点""证据不足"独立。
4. "用户认可"问卷（10 题以内）：想多看/少看的类目；在 3 个议题上希望看到两边还是一边；每天希望刷多久。

**输出**：`docs/definitions_v1.md`（类目、命题、标签规范、问卷）。
**验收**：5 人用同一批 20 条视频试标，分歧讨论后规范定稿。
**偏差**：议题只有 3 个，且由数据密度而非重要性决定。

### WP1 内容标注流水线（第 2–4 周，C 主责，全员轮换标注）
**做什么**
1. 从 KuaiRand-1K 标题中按关键词取每个议题的候选视频，按曝光次数排序取前 3,000 条（三议题共约 9,000 条，覆盖该议题大部分曝光）。ShortVideo 的对应标题（两性 496、育儿 114）作为第二来源。
2. DeepSeek 初标：输入标题 + 话题标签 + 类目，输出 JSON（是否相关、是否表态、立场、一句话证据）。费用：约 9,000 条 × 约 120 token ≈ 110 万 token，**约 2–3 元**；开思考模式约 10 元，先在 300 条上比较两种模式再定。
3. 校验：在 C-STANCE 的相关领域子集上跑同一提示词，报告 F1，作为噪声的外部参照；人工双标 300 条（每人 120 条，约 4 小时/人），算 κ 和混淆矩阵。
4. 噪声校正：用混淆矩阵对"立场分布"做校正（分布层面，不改单条标签），给出区间。

**输出**：`data/annotations_v1.parquet`（不进 Git，发清单）；`analysis/labeling/` 脚本与评估报告。
**验收**：人工双标 κ ≥ 0.6；LLM 对人工多数票的 macro-F1 报告出来（预期 0.6–0.7，低于也接受，但要报告）。
**偏差**：只用文本；标签有噪声。

### WP2 镜子：两维分数与个人报告（第 3–6 周，A 主责，E 做报告模板）
**做什么**
1. 对 KuaiRand-1K 的 1,000 个用户，按固定曝光窗口（每 200 条一个窗口）计算：
   - 主题维度：主导类目占比、归一化熵、覆盖、持续性（主导类目跨窗口稳定性）、重复性（同视频/近重复，用已验证的标题向量）；
   - 观点维度：对 3 个议题，窗口内可判定曝光的立场分布、主导立场占比、按 Draws & Tintarev 的 nDJS 算倾斜；可判定曝光 < 20 条则输出"证据不足"。
2. 参照系：① 用户自己前 7 天的分布；② 群体分布；③ 随机曝光池的分布（作为"不个性化"的近似，写明局限）。分数用 RADio 式的 JS 散度表达"相对参照的倾斜"。
3. 用 KuaiRec 全观测矩阵验证主题维度：在"看到一切"的参照下，推荐分布的倾斜如何。
4. 个人报告模板（notebook 渲染为静态页）：两维并列、按议题卡片、趋势、代表性视频、证据质量、参照对比；区分观察与仿真。
5. 对比平台自带功能：抖音"内容偏好评估"只有 25 类标签占比，我们多出观点维度和参照对比。

**输出**：`analysis/mirror/` 脚本；1,000 用户的分数表；3 个示例报告（含一个"主题多样但某议题单边"的案例，如果数据里确有）。
**验收**：评分器通过组员路线图里的 7 个对照案例（单主题多观点、多主题各自单边、全无观点、同比例不同排列、重复重播、议题消失、单边候选池）。
**偏差**：匿名用户没有自述标准；"不个性化"参照是近似。

### WP3 按钮：控制手段的真实效果（第 2–7 周，B 主责事件研究，D 主责仿真）
**3a 代码事实（已完成，维护）**：`analysis/data_check/x_mapping_and_levers.md`，按 X 版本更新一次。
**3b KuaiRand 事件研究（核心，新）**
1. 事件：hate（10,713）、follow（11,398）、like、long_view；对每个事件取前后 30/100/300 条曝光，算该类目、该作者的占比变化。
2. 对照：同用户随机时点；同用户同类目的正向事件；回归到均值校正（事件前窗口与更早窗口比较）。
3. 异质性：按用户活跃度、按事件时的类目占比分层；作者层面（hate 之后同作者是否再出现）。
4. 不确定性：按用户聚类的自助法；报告效应量与 95% 区间。
5. 可选扩容：KuaiRand-27K（9.9 GB，hate 事件约 27 倍）。
初步数字（已跑，待严格化）：hate 后类目占比 7.3% → 6.9%，long_view 后 10.7% → 11.1%。
**3c 仿真开关实验**：见 WP4。
**3d 跨平台对照表**：TikTok（Kaplan 2026：不感兴趣 −84%，划走 −48%，停手后复发）、YouTube（Liu 2024：−88% 首页；Mozilla 2022 真实用户：11–43%；Hosseinmardi 2024：约 30 条内"忘记"）、快手（3b）、X（3a：软信号、话题级默认关闭）、我们的仿真（3c）。统一列：幅度、见效速度、复发、证据等级。
**3e 自我审计（可选，C 级）**：3–5 名组员各一周，记录每天前 50 条推荐，中间两天关闭个性化；在一个类目上连续点 20 次"不感兴趣"记录前后变化。只用自己的账号，知情同意，匿名报告。

**输出**：`analysis/buttons/` 事件研究脚本与报告；对照表。
**验收**：事件研究结果在三种对照下方向一致；每个数字带区间。
**偏差**：真实平台效应只有观察性证据；复发没有自己的真实测量。

### WP4 代价与复发：仿真（第 4–8 周，D 主责）
**做什么**
1. 更新 `sim.py`：不感兴趣权重 −47.52、点击 0.3、点击后停留 0.4（单位作为敏感性参数）、冷启动 Thompson sampling。
2. 校准：用户对茧房外类目的接受度曲线（已有）；个体差异（易进茧房/爱探索两型）；用 3b 的事件研究结果校准"不感兴趣"的作用范围（A/B/C 三种中哪种最接近快手的真实结果）。
3. 实验：造茧房（真实历史 + 拼接连续观看）→ 分别施加每种操作（不感兴趣、屏蔽关键词、静音作者、多看别的、关闭个性化）→ 记录回到参照距离内所需刷新/操作次数、放弃的喜欢内容数、停手后复发率。
4. 敏感性：NI 范围、停留单位、转发权重、DPP θ、冷启动开关；每组 ≥ 20 个种子。
5. 可选：L1 替代模型替换规则版，检验结论是否变化。

**输出**：`analysis/sim_v2/`；代价与复发表（区间）。
**验收**：所有结论在敏感性范围内方向一致才写成结论；否则写成"依赖假设"。
**偏差**：代价是仿真数，不是真人数。

### WP5 用户认可（第 3–6 周，A 主责，E 协调）
**做什么**：WP0 的问卷发给组员和愿意参加的同学、家人，目标 20–40 份；对其中能导出自己抖音/快手观看历史的人（预计 3–5 人），用 WP2 的镜子算一次，并与其自述对照。
**输出**：匿名汇总；3–5 个"自述 vs 镜子"案例。
**验收**：有知情同意文本；不收敏感信息；只汇总报告。
**偏差**：样本小，不代表人群；是案例不是统计。

### WP6 综合与产出（第 7–9 周，E 主责，全员写作）
1. **信息流使用手册**：每条建议标注证据等级（代码事实 / 真实日志 / 仿真 / 他人审计 / 案例）。
2. **镜子原型**：notebook 或静态页，输入曝光序列，输出两维报告。
3. **研究报告**与**展示**：围绕一个用户样例讲"察觉 → 操作 → 变化 → 代价"。

## 6. 成功标准（负面结论也算成功，只要证据扎实）

1. 一张带区间的"按钮效果表"：快手真实日志（我们的）+ TikTok/YouTube（他人的）+ X 代码（机制）+ 仿真（代价），每格有证据等级。
2. 1,000 个真实用户的两维镜子结果，以及至少一个"主题多样但某议题单边"的真实案例（或报告"未找到"）。
3. 纠正一次倾斜的代价区间及复发率，并说明它对哪些假设敏感。
4. 一份每条有证据等级的使用手册。
5. 所有标签噪声、许可证、数据局限都写在报告里。
