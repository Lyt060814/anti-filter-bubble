# Execution Plan v3：从公开资源到可检验的观点曝光助手

2026-10-03 · 最终执行基线，对应 [Working Plan v3](working_plan_v3.md)。替代 v2 的工作安排；保留历史数据、样本和结果。配套[资源调研与选择](resource_review_v3.md)、[本轮实测](../context-recovery/plan_v3_feasibility.md)。**本文中的工作包是计划；只有可行性记录明确标为通过的检查已经完成。**

## 1. 冻结什么，怎样判断可行

固定的是问题、证据标准、接口、验证和失败分支，不提前固定最佳模型。先追求效果完整的方案，再落实资源；不以旧 200 条、CPU、旧预算或只能做一个案例压缩目标。成熟方法可直接成为最终方案，Agent 不因名称先进而自动胜出。

项目定位为数据分析、算法／系统设计与动态建模的 hybrid。核心链条是：**多议题内容及语境 → 可核查的观点／理由表示 → 曝光镜子 → 确认目标 → 干预与补充 → 多环境动态复查**。完整上线 app 不属于必需交付。

“可行”分开记录：数据可取得、组件可运行、方法适用、结论可识别。下载通过只支持第一项；推理通过不证明准确；离线准确不证明真人获益。本版不能诚实地保证每个理想实证都成功，但为每个缺口规定仍可完成的分析／设计和结论边界，不把失败分支冒充主方案实现。

最终规划不再滚动扩题。按冻结协议进行的模型选择、校准、抽样和参数决定记入实验登记；必须改变研究问题、测试集用途或核心判据时记录原因、时间和受影响结论，不覆盖原记录。

规模由要回答的问题决定：开发 pilot 用于估算分歧和支持数，正式审计按错误率／区间精度、稀有标签与聚类效应规划。可用二项比例最坏情形 `n≈1.96²×0.25/e²` 作独立样本量起算（误差 ±5 个百分点约 385），但按视频／作者聚类、加权抽样、不可判定和每标签支持修正，不能把总量 385 当所有任务保证。内容、检索审计和用户／序列评价的样本量各自确定。

## 4. 八个工作包

### WP0：问题、参照、协议和选择登记（A 主责，E 复核）

**做什么／为什么**：冻结 Q1–Q3、标签、用户任务与可支持的主张，避免跑出结果后重新定义“成功”。

**方法**：对既有研究按研究对象、控制能力、测量层和结论强度比较；把用户目标分成减少表达、保留议题／条件、补充有来源理由及单边过滤边界任务。来源覆盖不是所有合理观点的全集，目标也不是强制正反各半。

建 `protocol.md` 和 `method_decisions.md`：逐模块列候选、输入、指标、开发比较、采用／弃用理由、现实依赖和未识别参数。定义“精度不足就拒答”“保留约束不满足就不给该操作建议”等失败输出；具体阈值经开发材料设定后冻结。

**验收**：每个主张能指出数据类型、分母、参照和反证；团队两名非执笔成员能复述同一用户问题。读到的文档建议不自动成为团队命令，课程附件以原文为准。

### WP1：数据扩展、检索与覆盖（B 主责，C 配合）

**做什么／为什么**：得到覆盖多种困难的真实材料和可测轨迹，而非只分析旧关键词池。

**方法与顺序**：

1. 用 ShortVideo、KuaiRand 标题／封面、可关联语境构建源内索引；保留全部数据池描述，先检查跨源 ID 不能相连的问题。只对实际可取得内容宣称可用。新采集或本人导入作为独立来源记录。
2. 比较词法、语义、混合及需要时的多模态检索／重排。用聚类和模型提出候选议题，人工确认可判定命题；婚恋、育儿、职业等是候选情境，彩礼不优先。按困难类型、语言及数据覆盖选开发与留出结构。
3. 分层抽查命中与未命中；报告加权误收、漏收估计与不确定性，不把便利例子当召回率评估。新查询只用开发结果改进，独立检索审计另锁定。
4. 对所选内容取得允许访问的视频、ASR／字幕、音轨和必要上下文，记录逐条成功／失败／缺失。批量下载遵守作者并发要求。媒体本身与截帧派生物各留哈希和处理版本。
5. 对每个用户—议题检查曝光数、确认相关数、可判定数、时长、入口与缺口。固定曝光数窗口和日历窗共同报告；稀疏数据不能拼接成连续 feed。
6. 新增 KuaiSAR 只用于搜索／推荐行为结构及转换假设；检查版本、时间戳和 hashed 字段。是否扩到 KuaiRand-27K 由轨迹覆盖、用户异质性和稀有反馈精度缺口决定；不为下载量扩容。

旧 200 条登记实际用途，旧 524 事件仍服务 WP4。ShortVideo 本轮 8 条配对媒体是便利技术检查，不能作为已冻结的开发／测试集，也不证明三个议题都已得到有效命题材料。

**输出／验收**：资源—字段—许可—缺口表，数据清单、检索审计、议题划分、个人轨迹准入与排除原因；报告视频数、曝光数、用户数必须对得上。完整留出材料由 A/E/B 保管，不向模型开发者提前暴露标签或反馈。

### WP2：多模态证据表示与模型选择（C 主责，全员标注）

**做什么／为什么**：正确区分作者观点、角色台词、条件和理由，使下游报告与控制有可靠依据。

**同一批材料上的开发比较**：

| 条件 | 实际输入／候选 | 要检验的新增价值 |
|---|---|---|
| M0 | 标题文本＋规则或文本模型 | 可用低信息基线和失败类型 |
| M1 | 标题＋ASR／字幕，文本 LLM | 语音／字幕是否消除标题歧义 |
| M2 | 采样帧／片段＋转录，适用 VLM | 角色、引用、画面文字与时序理解 |
| M3 | 支持音频的视频模型联合输入 | 音画关系、语气等是否提供额外有效证据 |
| 流程对照 | 固定 AI 流程 vs 按需取证 Agent | 相同资源预算或同等质量目标下，证据支持、误删及调用成本的变化 |

比较模态价值时尽量固定模型或明确架构混杂；不得把“换模型且加视频”的全部提升归于画面。媒体不全的样本不从主审计里删除，另报各模态配对子集的选择偏差。

按模型实际支持建立输入；VLM 未读取音轨时单独转录。时间戳对应真实片段，缺少对齐就使用粗粒度证据范围，不能生成精确定位。ASR 和 OCR 错误、开头信息不足、缺失转折均是审计项。

人工先在多议题 pilot 独立双标，讨论定义后冻结；正式随机审计双标和第三人裁决，保留原始分歧与未知。用于改进的高风险主动复核另记，不混入总体准确率估计。模型辅助预标不提供给独立金标准标注者。

**选型指标**：各标签支持数／混淆、precision/recall/F1、角色和条件错误、证据支持率、理由多标签覆盖、回答错误率—覆盖率、下游误删／误报。以独立校准样本选择拒答／升级人工门槛；小样本不能承诺分布外风险保证。模型自报置信只作为待检验信号。

**输出／验收**：固定版本模型与提示、模态和取帧设置、原始预测、人工表、失败案例、每议题结果。首次采用大模型前先完成真实媒体输入→结构化输出→依据核查的小批试跑；若无法运行，记依赖未落实，保留完整接口设计和已验证分支，不宣称 M2/M3 完成。

### WP3：证据镜子与时间诊断（A 主责，B 统计，E 呈现）

**做什么／为什么**：把内容标签变成用户可以理解和纠错的曝光结构，帮助尚未察觉问题的人。

**方法**：并列总体议题量、同命题立场、理由／叙事、不同视频与来源、未知和时间。与个人过去、明确目标、来源目录或研究样本比较时分别命名。用稳定窗口统计为主候选，需要时比较变化点方法；JS 仅用于兼容的概率分布。未知范围与抽样区间分报，错误传播用独立审计和敏感性重算。

来源归并用 ID、引用、近重复等证据；相似模型只提出关联候选。报告中的关键提醒能回看材料，删除或修改标签后可重算。界面同时显示“为何值得关注”和“为何尚不能确定”，不输出伤害总分。

**验证**：真实候选池报告、准入的个人轨迹、构造和仿真序列分别出表。独立序列覆盖合理专门兴趣、多话题但同题单边、正反均有但理由重复、供给单边、未知较多、持续集中与突变。按整段观察期检验误报、检出、拒答和延迟，反复滑窗不能视为独立样本。

**输出／验收**：可复算报告和重算脚本；找不到合格个人轨迹时输出覆盖审计及构造／仿真检验，明确真实个人诊断性能未验证。

### WP4：操作能力、真实行为与外部证据（B 日志，D 源码，E 文献）

**做什么／为什么**：知道实际能操作什么，以及动态模型中哪些是已有依据、哪些只是未知假设。

**机制**：固定 X `b79b947ce9283c786822274ef8fe208c33c585b2`，检查硬过滤、多目标评分、探索／多样性和反馈路径；必要时运行隔离模块，再有条件跑 Phoenix nano。`−47.52` 是预测概率项权重；5% 遥测采样不是推荐多样性；1,024 不是全部平台记忆长度；excluded-topic 硬过滤通路存在。不能把源码默认值说成生产值。

**日志**：沿用 v2 已冻结事件协议：`tab=1`，前 200／后 100 条完整，每人最多前 5 事件、相邻选中位置 >300，524 事件／205 人。比较同作者早前 100、紧前 100、后 100；事件本身不入窗口。先用户内平均，再用户等权和整用户 bootstrap。预定首事件、邻近其他 hate 排除、72 小时子集和前窗零曝光诊断；空集 N/A。`is_hate` 不补写成已核实 UI 名称。同作者结果首先是关联，不是同观点因果效果。

**充分利用其他数据**：KuaiRec 在其有限池比较历史反应代理；KuaiRand 随机段检查选择偏差和可支持的行为验证；KuaiSAR 检查搜索前后转换、时间批次及字段缺失。各模块预先写主分析和分母，不能比较很多窗口后仅保留显著结果。

OPE 先审计 logging propensity、候选支持、目标策略、结果与历史。具备条件才使用 IPS/SNIPS/DR 并报告有效样本量、权重敏感性和区间；不具备则交付不可识别说明，不用估计器补造按钮长期因果效应。

**外部验证**：从已有 TikTok/YouTube 审计中选择与主张最直接、公开数据确实足够的一项结果按原定义复算，再检查本项目所需指标是否可计算。逐项报告复现范围；无法取得素材或标签时只作文献证据，不阻塞其他工作。

**输出／验收**：能力与机制表、日志关联报告、数据支持边界、关键文献复核。将“有源码”“有观察”“有随机实验”分列；不合成跨平台按钮排行榜。

### WP5：目标理解、来源补充和策略比较（E 主责，D 实现，C 核查）

**做什么／为什么**：让用户能表达“少看这种表达、仍想了解这个问题”，并比较真实可执行的办法。

LLM 提取结构化 T/K/A 与例外，用户确认；设计任务用于离线测试。目标冲突、边界不明时澄清，不自动选替用户决定的目标。Qwen-Agent 或 InteRecAgent 的意图—工具分工可复用，但不是现成反茧房应用。

对每个议题建立带版本的真实来源目录。混合检索／重排找到补充材料，核查其主张支持、新增理由、条件和与已有来源的关系。目录不完整就报告剩余缺口；LLM 生成的意见不算新的外部证据。

**静态比较**：不处理、整话题删除、关键词／作者控制、语义过滤、约束过滤＋去冗余＋来源补充。人工真值 oracle 与可改推荐器的 UCRS 类上界单列，不能给真实算法偷看真值。

对候选策略先检查能力和保留约束，再输出 Pareto 取舍：目标残留、议题绝对保留、理由新增、证据质量、未知误删、空缺位置、操作与阅读。估计标签上的约束满足不等于真值保证，独立人工审计必须计算实际违约。相关性与新增理由分别评价，不能让 MMR 向量距离代替观点充分性。

**Agent 试验**：固定流程与工具调用 Agent 同任务比较。工具白名单为取证、检索、读来源、计算、列动作；不让外部内容改变系统目标。自动平台动作只有接口能力和用户授权确实存在时才进入工具；否则给手动辅助。执行失败、建议被拒绝和补充没找到都作为结果。

**输出／验收**：目标确认实例、来源目录、策略比较和人可读操作说明；按预测选方案、按独立标签评价。给出至少一个“不能同时满足目标”的例子，说明取舍而不是强行输出成功。

### WP6：经过校验的动态实验（D 主责，B 训练与统计，C 语义模型）

**做什么／为什么**：解释操作在推荐反馈中怎样生效、保持和失效，是核心工作包。

**6a 共同接口。** 内容世界、推荐器、用户、干预助手、评价器各自版本化。用户接口为 `observe → respond → update`，推荐器为 `retrieve/rank → ingest_feedback`，干预器只读取可观测信息和目标。真值与预测、平台分发与实际可见、外部补充三条流分开。用手算小实例先核查状态、时间、成本、访问边界和未知处理。

**6b 用户模型。** U0 透明规则；U1 学习型多行为／序列响应；U2 接收真实内容语义与历史前缀的 LLM/VLM Agent；U3 语义特征＋统计概率与记忆的混合。U3 是优先检验假设，不是已经选出的赢家。

- 用 KuaiRand 等同源日志拟合可观测反馈，遵守用户／时间隔离；内容语义必须匹配到对应源和版本。视频模态条件只在真实存在的同源子集成立。
- U2/U3 人设不从年龄／性别直接推断观点。历史互动表示反应，不自动表示认可；显式反思目标另存。模拟用户不能接收“证明我们的助手有效”的提示。
- KuaiSim 的模型与训练流程可适配，但需重新处理字段、训练、校准。先核查并修正本轮发现的特定模型—环境路径重复 sigmoid 合同，修正前后分别保存，不沿用未经校准的概率。退出规则和 retention 生成机制单列，不作真实心理规律。
- LLM_User_Simulator 公开方法可借鉴；本轮发现默认 loader 和模型路径所需资产未提供，不安排“一条命令完整复现”。适配的特征／概率融合有独立规范。
- 外部阅读如何改变参与、建议遵从、兴趣变化与信念变化没有直接标签时只做情景参数。信念更新不纳入默认已验证结果。

**6c 模拟器资格检查先于策略测试。** 开发数据选参数，独立数据比较常数／频率基线、U1/U2/U3 的 log loss、Brier、GAUC（合格用户）、稀有反馈 PR、校准及用户异质性；不只报 AUC。检验连串行为、重复、会话统计和多步漂移；在历史上验证到哪一步就写到哪一步。Agent 另做提示改写、重复采样、模型家族与记忆失真检查。保留旧 LLM pilot 的未显著优于 logistic 的证据，不拿新设计自动覆盖它。

若 U3 无收益则不采用；若所有数据模型都不足，动态工作仍以透明情景分析完成，并明确现实预测资格未通过。不得通过扩大人设或减少难例掩盖失败。

**6d 推荐环境。** R0 透明反馈／遗忘／探索模型；R1 用真实历史训练的成熟排序／序列推荐模型；R2 固定 X 可运行模块或明确按代码重建的机制条件。R2 部分复现与完整 Phoenix 部署分别命名。公开模型不等于生产系统；为每个 R 定义反馈泛化、跳过处理、更新周期和候选供给。

**6e 策略与阶段。** D0 无新增显式干预，D1 负反馈，D2 有保留约束的本地过滤＋来源补充，D3 反馈＋定向搜索／关注；需要时比较 D2+D3，整话题控制作损失对照。将搜索、关注拆开作机制消融；可改平台上界独立报告。

阶段：自然热身与可能的集中 → 给定或确认调整任务 → 干预 → 后续。不人为规定所有用户必须形成茧房；包含供给单边、没有明显集中和合理专门兴趣。后续分继续、停止且不外加改变自然倾向、停止并增强原目标参与三类；目标改变单列，不称复发。

**6f 规模、配对与敏感性。** 初始工程预跑建议 10 用户×100 步，用于测耗时、token、内存、语义缓存和状态正确性，不作性能结论。正式规模按置信区间精度和模型差异选定：每个主环境先计划 4 策略×3 后续×20 独立世界 seed＝240 次；20 是起算而非充分性保证。Agent 的重复采样嵌套在世界中，不算额外独立用户世界。

选择至少一种透明和一种通过资格检查的语义／数据环境；策略开发与最终评价保留不同用户模型或机制条件。不要无理由全交叉全部模型。每个主环境分别报告结果；失败或缺席的环境照样登记。共享初始世界、供给与可配对随机流；模型调用持久缓存原始输入输出，分开纯机制随机性与模型随机性。

预定敏感性：负反馈泛化、历史遗忘、探索、候选理由供给、内容错误／未知、建议遵从和干预停止。先单因素，再针对会改变结论的交互，不用大量网格替代模型验证。报告策略排序是否随环境翻转。

**6g 指标。** 在开发阶段冻结任务阈值、窗口和观察期；至少连续 3 个规定窗口联合满足目标减少、信息保留与补充要求才记达标。同时报告绝对曝光和同议题比例、理由／来源、未知、操作、额外阅读、维护与反弹。控制器认为达标和真值达标分列。未达标右删失；复发同时报告先达标分母、全体轨迹和选择差异。统计以独立世界 seed 汇总／配对，不将同世界 50 个用户当 50 个独立实验。步数不换算真人分钟。

**输出／验收**：环境规格与参数证据来源、模型资格报告、配置、运行清单、原始轨迹、策略结果和失效地图。即使没有稳健胜者，也要能解释哪些假设决定结果。旧 pilot 只复用代码结构，不能沿用其类别指标和外加复发机制作新版结论。

### WP7：迁移、用户任务、整合与课程交付（E 主责，全员）

**迁移**：冻结开发流程后在整议题留出集作首次预测；随后开放独立少量适配集，第二次预测仍在未揭盲测试集上进行。A/E 双标、B 裁决保管，C/D 适配；两次结果锁定后再合并评价。报告仅替换议题定义与少量适配的结果、人工时间和需要改动的部分。跨议题成功不自动支持跨平台／跨语言。

**用户任务设计是核心，实施按实际条件。** 比较类别饼图、证据镜子、镜子＋行动辅助：能否识别观察与推断、找依据、纠错、表达目标、选择满足约束的动作；记录完成率、错误、时间和负担。采用经同意的参与者与平衡任务顺序，样本量按评价目标确定；组员技术自测不冒充用户研究。长期认知和现实平台因果效果需要另行设计。

**闭环与工具**：至少给出一个贯通发现、证据、目标、策略和动态复查的案例，标清每段材料类型。可选 notebook／本地工具用于导入、回看、更正、确认、补充和复查；不要求做 app。只有输入确为个人连续曝光才称个人 feed 报告。

**课程材料**：4–6 页 Plan、约 5–10 个精选来源、期中材料、最终报告、个人记录／反思、10 分钟演示与离线备份。内部 v3 不自动更新旧 PDF/Word，也不表示已提交。说明每个技术模块的输入输出、算法／伪代码、误差、实例及适用边界，避免八个模块各讲一段却没有同一问题。

## 5. 理想方案的实际差距与应对

| Working 理想能力 | 可以推进的主方案 | 未具备条件时交付／不能声称 |
|---|---|---|
| I1 完整曝光 | 源内连续性审计；合格子集；条件允许的授权导入 | 内容池和构造轨迹；不能称完整个人经历 |
| I2 完整理解 | 配对音画、VLM/Omni、取证 Agent、人工审计 | 已核查模态上的模型／人工流程；未运行大模型就不称其效果已验证 |
| I3 真实目标 | 真人确认；独立任务协议 | 设计目标与遵从情景；不能说匿名用户真正想要什么 |
| I4 持续诊断 | 真实轨迹＋误差传播＋完整序列验证 | 局部及仿真验证；真实发现速度未知 |
| I5 平台与本地控制 | 能力匹配、人工／工具辅助、来源补充 | 无接口时只手动说明／本地操作；不称改变生产排序 |
| I6 长期可信比较 | 经过检验的多用户／多推荐环境、有限池与日志对照 | 条件化机制结论；不保证真实逃离概率、时间或按钮因果效果 |
| I7 人的收益 | 理解与操作任务；后续另设长期研究 | 完整研究协议与技术演示；不宣称真人福利改善 |

因此不存在依靠更大模型消除所有差距的“100% 现实效果保证”。能保证的是任务明确、入口有证据、失败可解释、设计和验证产物可交付；语义准确、动态真实性与实际收益需要分别得到结果支持。

## 6. 执行节奏与决策门槛

课程日期暂按附件，最终以 Moodle 为准。主依赖是 WP0→WP1/2→WP3/5→WP6/7；WP4、模拟接口和资格验证可从第一阶段并行推进，不能等所有标签完成再开始。此处“并行”是小组分工，不要求多 Agent 系统。

| 时间 | 关键交付／决定 |
|---|---|
| 10-03—10-04 | v3、调研和可行性记录；团队据此压缩课程 Plan，填真实成员姓名；10-04 暂定截止 |
| 10-05—10-11 | 多议题 pilot、留出隔离、样本量与协议；落实模型环境和真实媒体小批试跑；模拟接口与数据支持审计 |
| 10-12—10-18 | 独立内容审计、模型选型、检索与轨迹覆盖；镜子、来源目录、静态干预；用户模型一步资格报告 |
| 10-19—10-24 | 期中闭环案例、模拟多步检查和正式配置冻结；留出首次预测；真人协议具备条件才启动 |
| 10-25—10-31 | 动态主比较、敏感性与跨环境检验；迁移适配与盲测；外部审计可复现部分 |
| 11-01—11-10 | 全部结果与失败边界、用户任务结果或未实施说明、关键图表与报告复算；个人日志暂定 11-04 |
| 11-11—11-15 | 论证、引用、正文与演示备份、个人反思；最终报告暂定 11-15 |
| 11-17/19/24/26 | 按课程实际安排展示 |

阶段门槛：**G1 输入可追溯；G2 语义误差足以支持所声称的控制范围；G3 静态目标与保留可检查；G4 模拟器资格及未验证假设明确；G5 跨环境／议题与最终主张匹配。** 未过门槛就缩小相应能力主张或改用通过验证的方法，不把负结果删掉，也不把扩展失败变成只做类别饼图。

工作量不作为理想设计上限。执行首周记录各步骤真实吞吐：标注条数／人时、视频秒数／推理秒数、token／调用、GPU 时、下载量与失败率、每世界运行时间。预算按 `各阶段样本量×实测单位成本＋独立复核与返工` 计算。模型缓存、批处理、语义特征复用可减少重复开销；缓存不能把应当独立的 Agent 随机重复变成复制同一次输出。需要外部算力的依赖未落实时明示，不编造费用和已获额度。

## 7. 五人分工、交接与最终验收

| 成员占位 | 主要贡献 | 独立复核与交接 |
|---|---|---|
| A | 问题、标签、镜子、误差与参照、WP0/3 | 动态成功标准；与 E 保管留出测试标签 |
