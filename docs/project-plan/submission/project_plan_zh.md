## 1. 问题与方案概念

一个经常看育儿视频的人，可能反复听到“只有严格管教才能培养出优秀孩子”。他的信息流里仍有美食、音乐和旅行，按内容类别统计，看起来并不单一。但在育儿这个议题内，同一种解释可能长期占据主导。他希望少看武断的概括，同时继续了解管教方法，而“不感兴趣”按钮很难表达这种区别。

本项目的问题是：**短视频用户如何发现日常议题中持续存在的观点与理由的局限，并在保留所需信息的前提下调整自己的曝光？**

我们关注中文短视频中的**信息茧房风险**：在育儿、婚恋和职业选择等议题内，推荐与用户反馈可能反复强化有限的观点和理由。英文采用 **filter bubbles**，突出个性化推荐这一情境；**观点曝光**是具体测量对象，不等于已经证明算法因果或危害。兴趣集中不一定有害，也不应强行平衡正反方。真正值得关注的是用户未察觉、或难以按自身意愿改变的选择性呈现。

方案包括三个部分。首先，用**曝光报告**展示反复出现的主张、理由与来源，并提供可回看的例子。其次，通过**目标确认**明确用户想减少、保留或进一步了解什么。最后，**比较并复查调整办法**，分析它们能否达到目标，以及需要多少持续操作。例如，用户可以要求减少“严格管教是唯一有效办法”的表达，同时保留具体建议和不同做法的解释。

我们将在至少两个议题上共同开发方法，再用一个未参与开发的议题评价适用性。主要成果是带证据的报告设计、干预策略比较和动态仿真；条件允许时用小型工具演示，不要求完成一个 app。研究重点是曝光与控制，不直接测量用户信念或生活质量的改变。

## 2. Computing 与 data science 方法

本项目属于**数据分析、算法设计与仿真建模相结合的 hybrid project**。技术重点是：在保留有用信息的约束下选择调整办法，再分析它们在“推荐—反馈”循环中的效果。已有方法适用时直接采用，不要求发明新算法。

### 理解内容

先用关键词和语义检索寻找相关视频，再识别具体命题、发言者立场、理由和视频中可见的依据。大语言模型（LLM）可分析标题与转录；涉及对话、字幕或画面语境时，视觉语言模型（VLM）可结合片段与画面进行判断。剧情角色的一句台词不能直接算作作者的观点。

模型输出须附依据片段，并允许回答“无法判断”。两名成员将独立标注评价样本，处理或保留分歧，再检查模型错误。通过比较标题、加入转录和加入音画三种输入，判断额外语境何时有帮助。检索也需要评价，包括初次搜索遗漏的相关内容。

### 描述曝光

针对具体议题，统计立场分布、重复理由、同一来源材料的反复出现及时间变化。参照可以是用户过去的信息流，也可以是有出处的相关论据集合，但两者都不自动代表“正确分布”。报告会展示缺失材料和不确定标签，不把所有现象压成一个信息茧房分数。

这里必须区分内容集合与个人曝光记录。只有日志中存在足够相关观察时，才生成个人时序报告；否则说明覆盖不足，并用明确标注的构造序列检验报告方法。

### 比较调整办法

控制环节的输入是用户确认的“减少什么、保留什么、补充什么”及允许采取的操作。我们将比较不干预、整话题过滤、针对性负反馈、选择性过滤与有来源的信息补充，以及主动搜索或关注。比较时会区分平台自带操作与拟议外部工具提供的过滤、信息补充功能。

采用简单的约束选择方法：先排除会删去过多所需信息的策略，再比较剩余方案中的不希望看到的曝光量、信息保留、新增理由和操作负担。语义相似度可以帮助检索，但不能单独判断材料是否提供了新的理由。LLM 助手可澄清需求、调用搜索和分析工具，具体统计与约束判断仍由可复查的程序完成。

### 检验动态反馈

仿真分别表示内容池、推荐器、用户和干预策略。每一步中，推荐器选择内容，用户作出反应，平台更新行为历史，再产生下一轮推荐。用户容易停留观看的内容，与他希望调整后的信息流，分别建模。

我们将比较透明的规则用户、数据驱动用户和 LLM 用户。一个值得检验的方案是：用模型理解内容含义，再结合统计模型预测可观察行为。有配对内容与日志时，先用留出的真实记录检验行为预测；能说出合理理由，不等于行为真实。如果更复杂的用户模型缺乏依据，仍保留简单仿真来分析机制。

实验将比较持续干预与停止干预，并改变推荐记忆、探索和负反馈响应等假设。记录目标是否达到、所需曝光步数、有用信息损失、操作次数，以及不希望看到的模式是否再次出现。通过重复运行检验结论对模型假设的敏感性；仿真不代表真实平台的完整复刻。

## 3. 相关研究与本项目的切入点

**参与行为与用户意愿可能不一致。** Milli 等 [\[1\]](#ref-1) 在 Twitter 政治内容研究中发现，按参与度排序与用户自述偏好并不一致；按自述偏好排序又可能强化与自身立场一致的内容。这说明需要区分“吸引注意”与“用户想要”，也不能把用户控制当成自动有效的解决办法。Vera 和 Ghosh [\[2\]](#ref-2) 通过对 14 位 TikTok 用户的访谈，记录了不想要的推荐及清除这些内容的尝试，为本项目的生活情境提供依据，但不能据此推断中国用户的发生率。

**观点分析需要超出类别统计。** Pecher 等 [\[3\]](#ref-3) 的 TikTok 审计区分了话题变化与立场变化，因此“研究同一话题里的观点”本身并不是空白。Draws 等 [\[4\]](#ref-4) 在搜索结果研究中从立场和背后的论证逻辑理解观点多样性。我们借用这种区分，并面对短视频中的角色、语境缺失和重复故事等判断困难。

**用户控制已有成熟方法。** Wang 等的 UCRS [\[5\]](#ref-5) 允许用户通过特征层面的控制影响推荐。本项目面对的是用户通常无法修改平台模型的情况：如何表达“继续了解这个议题，但调整某类表达或补充某种理由”，再通过手边的操作实现？X 的公开推荐代码 [\[6\]](#ref-6) 提供了可检查的过滤和评分机制，但不能证明中国短视频平台采用相同规则。

**公开数据与仿真支持部分验证。** Shang 等发布的 ShortVideo 数据集 [\[7\]](#ref-7) 将内容与行为联系起来；KuaiRand [\[8\]](#ref-8) 提供时序互动和随机曝光视频，可用于内容分析及行为检验，但都没有记录用户经过思考后确认的调整目标。SimTok [\[9\]](#ref-9) 展示了由 LLM 用户读取视频文本描述、与推荐器反复互动的模拟方法。Yoon 等 [\[10\]](#ref-10) 则说明，模拟偏好和反馈需要独立对照真人数据。因此，我们会把用户模型是否可信与干预是否有效分开评价。

这些研究为我们留下了一个具体问题：**能否从用户侧识别生活议题中反复出现的理由，把具体调整目标转化为可用操作，并比较信息损失和持续维护的代价？** 本项目将在多个议题、内容判断不完整和平台权限有限的条件下研究这一问题，而不是提出新的推荐算法。

## 4. 可行性、局限与伦理

我们已经取得公开短视频内容与互动数据，检查了视频与转录的配对，并完成语义检索和用户响应模型的初步运行检查。这些说明数据入口和基础运行路径可用，不代表内容判断已经准确或仿真已经真实。

试标结果将指导样本选择，以覆盖重要情境并评价错误。我们会复用预训练模型和成熟统计方法。较大模型的推理需要合适算力；若资源不可得或效果不佳，仍可用人工核查的内容分析，并在透明仿真中展示控制逻辑。报告会区分已实现部分与仍停留在设计层面的部分。

主要局限是视频语境不全、个人轨迹稀疏、平台响应未知。负反馈前后的日志变化首先作为关联，不直接解释为因果效果；仿真结论也保留其假设条件。接触更多观点不证明判断更好，过滤不喜欢的观点还可能进一步缩窄信息流。因此，我们会展示取舍，也不会在证据强弱不同的情况下把相反说法视为同样可信。

核心工作使用公开研究数据与模拟用户。离线实验的调整目标将作为测试情境预先设定，不把它们当作匿名日志中真实用户的意愿。我们将遵守数据使用条款，不识别个人，在共享输出和示例中去除不必要的个人信息。若使用外部 AI 服务，需符合数据允许的用途，并避免发送可识别的个人历史。真人测试属于可选部分；招募前会确认适用的课程或学校要求并取得知情同意。核心研究不需要自动操作真实账号或实施线上平台干预。
