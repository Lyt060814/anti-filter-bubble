## 1. 项目主线与交付层次

项目问题保持为：**如何帮助短视频用户发现同一日常议题中持续集中的观点、理由与叙事，并在保留有价值内容和自主选择的前提下，选择、实施、复查调整办法？** 用户可以尚未意识到问题；系统也应允许“没有必要调整”。并非任何集中都构成有害茧房。

定位为 **数据分析 + 算法／系统设计 + 仿真建模的 hybrid**。技术围绕四个相连的环节展开：内容表示与不确定性 → 曝光及时间诊断 → 有保留约束的干预与信息补充 → 动态反馈、维持与代价。文献和机制分析为这些环节提供定义、依据及边界，不另做一套脱离用户问题的研究。

| 层次 | 本学期安排 | 可以主张什么 |
|---|---|---|
| **核心设计与验证** | 多议题联合开发与整议题留出测试；共用数据结构；真实内容审计和可运行的有限自动处理；可复算镜子；干预比较；动态仿真；课程报告 | 哪些方法在明确输入、任务和假设下适用，代价与失效条件是什么 |
| **条件推进的实证深度** | 更好的现成内容模型、更完整语境、首轮之外的更多议题、满足条件的个人轨迹 | 只报告实际完成的领域、样本和验证；达不到条件时保留覆盖审计和原因 |
| **可选落地与真人评价** | 本地工具或交互原型、本人授权记录、理解／操作任务、前瞻观察 | 有对应证据才报告可用性、真实行为变化或认知收益 |

第一层必须贯通发现、干预、复查，不能只剩内容标签表；后两层用于增强外部适用性，不能让核心工作等待尚未取得的资源。**成熟方法适用就直接使用**：规则、已有 NLP 模型、常规统计、有限策略枚举和简单状态模型都可以成为最终方案，不要求算法原创、训练大模型或超过 SOTA。

**全流程选型约定。** 每个工作包先写“希望改善的结果—所需证据—成功标准”，再检索当前资源清单之外的适用方法，比较候选并保存选择依据。数据获取、检索、诊断、干预、仿真、评价与工具实现同样适用；不把“加入 AI”或“坚持简单方法”作为统一答案。候选可来自其他领域、开源工具、可获得的模型服务和成熟系统；旧代码和文档中的具体算法均可替换。先形成效果导向的完整设计，再落实资源与阶段；现有小批次、工时和 CPU 配置只描述起步路线，不排除更好的方案。

在 `docs/method_selection_v2.md`（待建）逐模块记录任务指标、候选来源、适用输入、比较设计、端到端影响、已验证结果与未落实依赖；官方宣称的能力和本项目实测分列。选型依据先于大规模运行；共同测试集保持独立，不能反复试到成绩最好再当成独立验证。无需穷举所有工具，但要说明所选候选为何覆盖关键选择，并在出现更适用方案时允许替换。

## 3. 与 Working Plan 理想能力的差距

| 理想能力 | 核心执行与条件推进 | 仍然做不到／不能推出的结论 |
|---|---|---|
| **I1 完整、经同意的个人曝光** | 公开历史日志做覆盖、密度和连续性审计；合格用户／议题子集才做轨迹报告；不足时使用明示构造序列 | 匿名日志不是本人确认的完整日常 feed；内容池不是个人曝光；不保证得到足够真实个人案例 |
| **I2 完整视频理解** | 文本人工审计、有限自动处理、24 ASR 对照；按实际缺口扩大语境与模型验证 | 无完整画面／角色语境时不能确定整条视频立场；语义模型和 ASR 都有误差 |
| **I3 用户明确目标** | 通用目标结构、确认流程及设计任务；允许减少、保留、补充、例外和不行动 | 设计任务不代表匿名用户的真实愿望；无真人任务就不声称偏好或接受度 |
| **I4 可解释、持续的镜子** | 议题线索、证据报告、未知范围、构造序列和仿真中的时序验证；合格自然轨迹再验证 | 没有自然轨迹就无法确认真实个人误报率和发现速度；参照不等于现实真值或“正常人”标准 |
| **I5 可执行的调整** | 现有平台能力表、有限控制策略、带来源的信息补充和操作说明；本地过滤可作示例 | 本地过滤不等于改变平台推荐；没有接口就不承诺自动操作；源码不能代替实测响应 |
| **I6 可信动态比较** | 固定反馈事件关联 + 多机制、多 seed 动态仿真；条件允许再做前瞻观察 | 日志变化不是按钮因果效果；仿真不能估计真实平台逃离分钟数或真实复发概率 |
| **I7 帮助人理解与改善** | 可核查案例、任务流程和组内技术复核；可选真人理解／操作评价 | 没有真人证据就不声称用户获益；即使理解任务成功，也不等于改善长期信念或生活结果 |

还有一个横跨各行的差距：**通用设计不等于通用性能**。首轮安排至少两个议题共同开发，另留至少一个完整议题做迁移检验，检查哪些定义与组件可以复用；自然数据缺失时，构造检验只支持设计可迁移，不支持该领域的真实准确率。跨平台、跨语言另需验证。

## 4. 工作包与接口

本版重新编号为 **WP0–WP7**，替换旧执行稿的 WP0–WP5；不要混用旧编号。全组共用三张逻辑表：内容证据、曝光事件、目标与行动，字段对应 Working §5.1。原始材料、人工标签、模型预测、任务标签和仿真真值分列保存。新增产物路径以下用代码格式列出，均为**待建文件**。

**数据设计先于样本数量。** 首轮选择来自不同生活情境的至少三个明确议题：至少两个共同开发，至少一个整议题留出；这是用于检查跨议题复用的起步设计，不代表覆盖所有日常议题。婚恋／家庭角色、育儿／教育、职业选择都是候选，彩礼没有优先或必选地位。按所检验的困难、实际内容和连续曝光覆盖选题，不能只选数据最多或容易做出好成绩的议题。每条记录带 `issue_id / proposition_id / split / sampling_version`，检索和标签定义可替换，后续统计、控制与仿真使用共用接口。

### WP0：问题、定义与验证协议（A 主责，E 复核）

**技术与工作**：将生活问题转为 Q1–Q3；定义话题、命题、立场、理由、叙事、角色与未知；整理“已有工作做到了什么／本任务缺什么”的证据表。用共用字段加可替换议题配置表示问题，不把“彩礼”写进通用统计和控制函数。

在多个议题上共同检查定义：例如彩礼安排中的条件与群体概括、育儿中的自主与管教、职业选择中的收入与稳定取舍。具体命题经试读后确定，不能把整类话题直接二分。命题支持、条件支持、反对、混合、未表态和语境不足分别记录，理由多标签并允许“其他”，引用、剧情和反驳不自动算作者认同。健康等证据不对称的问题可另作边界案例，检查是否错误追求正反平衡。

预先写三类任务：① 减少某类概括，同时保留议题及条件分析；② 保留已有兴趣，补充尚缺且有来源的理由；③ 减少某一立场的对照任务，用于检验“服从指令也可能使观点更窄”。第三类不是默认破茧目标。任务阈值来自明确说明或用户确认，不是通用伤害阈值。

**冻结与交接**：10-11 前根据多议题 pilot 冻结共同流程、各开发议题配置、规则／模型版本、阈值选择方式和评价分母；锁定留出议题及测试规模。测试结果揭晓后修改须新版本、新评估，不能覆盖旧成绩。留出议题可在首次预测后开放适配样本，但不能偷看其测试标签后声称零样本迁移。

**输出与验收**：`docs/definitions_v2.md`、`docs/evaluation_protocol_v2.md`、议题配置与约 5–10 项精选来源的主张表。两名未执笔组员能复述输入、判断条件和失效条件；不靠“观看=认可”“未知=中立”“两边各半最好”运行后续步骤。

### WP1：数据准备、议题发现与个人轨迹可测性（B 主责，C 配合）

**技术与工作**：对可获取内容做 ID 关联、去重、检索与覆盖统计；处理引擎按实际数据规模选择。关键词、语义、混合检索、重排和议题发现方法根据覆盖与误收表现选择，pandas 与词法检索可作起步实现而非必经阶段。用户尚未指定议题时，从内容提出候选议题并确认明确命题；该过程只产生线索，不自动宣布茧房。记录所用方法、版本、资源需求、有效新增内容和检索盲区。

1. 从已有完整内容元数据中检索多个候选议题，形成候选数、语境可用性、命题清晰度和曝光密度的比较表，再按上述检验需要锁定开发与留出议题。已有彩礼 200 条与哈希原样保留，可按新协议复用；改用为开发材料的条目须登记，不再冒充未见测试。分开保存内容池与曝光日志，同一视频多次曝光不能去成一次。
2. 每个开发议题先取 20–40 条 pilot，用于发现标签缺口并估计可判定率、标签支持数、分歧和处理耗时。然后按要估计的量、期望区间精度及可用数据确定独立审计样本量，在看测试成绩前锁定抽样规则和规模。留出议题单设测试及适配样本；首次预测前 C/D 不接触其标注或用其内容调方法。数量不足时报告精度与支持不足，不补选内容造立场均衡，也不因为好成绩而提前停样。
3. 对检索命中和未命中分别抽取材料复核，首批每议题各 50 条是检索审计的操作批次，不是内容评价样本量。根据首轮不确定性制定后续固定批次；未命中样本没发现相关内容也不宣称召回率为 100%。这些审计集与内容分类测试集分开，抽样权重和后续检索迭代分别记录。留出议题的审计由 A/E/B 保管，结果在对应预测锁定前不传给 C/D 用于调整方法。
4. 重新检查个人轨迹，而不是因旧关键词稀疏直接放弃：按用户、入口、时间列出总曝光、候选、确认相关、可判定、缺口和覆盖时长；比较固定条数窗与日／周窗。更宽检索和更长窗口可能增加样本，但会损失主题精度或时间分辨率，两者必须实测。

**已有约束**：此前 58,066 个全入口、不重叠的 200 条标准曝光窗中，至少 20 个候选的用户，宽婚恋／育儿／健康词组分别为 64／78／15 人，彩礼仅 1 人。这是当前检索的密度，不是全部真实议题含量；也不能套到 `tab=1` 事件样本。ShortVideo 的稀疏抽样不补成完整 feed。

**进入个人分析的条件**：按 WP3 在开发序列上确定的支持数、未知范围和连续窗口要求筛选；报告所有被排除者及原因。没有子集通过时，交付覆盖和不可测原因、内容池报告及构造／仿真轨迹，不能给全部用户强制评分。完整历史中的缺失不可由增加窗口长度修复。

**输出与验收**：外部版本化样本、分组清单和检索审计表；仓库中 `docs/analysis/data_coverage_v2.md` 与可复现处理脚本。候选视频数、曝光次数、用户数、抽样与过滤前后数量能对上；开发、迁移和自然轨迹的证据单位清楚。

### WP2：内容表示、自动处理与人工校验（C 主责，全员标注，A 复核）

**技术与工作**：把现成 LLM／VLM 纳入主要候选，完成命题条件下的立场／理由抽取、证据定位和选择性拒答；人工双标用于独立评价。数据来源与模型来源解耦：ShortVideo、KuaiRand 等提供材料，理解方法可以从已有资源之外选取。规则、已有立场模型和人工流程保留为对照，不要求先做完规则方案才使用 AI。

**选型与运行步骤**：以同一批多议题开发材料检验适用模型；开放候选包括 [Qwen3-VL](https://github.com/QwenLM/Qwen3-VL)、[InternVL](https://github.com/OpenGVLab/InternVL)，音轨转写可用 [SenseVoice](https://github.com/QwenAudio/SenseVoice) 等方案，画面文字可用 [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)。这些是官方入口已核查的候选，不是本项目已验证的最佳组合；开放权重、代码与各组件许可分别登记。先验证字段与模态，再运行成对的信息条件比较，最后冻结模型／权重版本、提示、采样帧率／片段、转写、输出格式及适用范围。只有标题的内容仍作为文本输入，不假造视频信息；VLM 不支持音轨时单独提供转写，必要时选择支持音频的方案。

**流程选择**：同时设计固定的“取片段／转写／OCR → 结构化理解”流程与按需补充信息的 Agent 流程。Agent 可根据缺口再次取片段、放大字幕、调用转写或交人工；记录调用、输入时间范围与结果。用有限开发对照确定它是否改善角色判断、依据定位、拒答与下游误删，不能只比摘要是否流畅。单个带工具的模型可以完成编排，不要求多 Agent。具体资源试跑和所需投入另记，现有工时表只是起步估计。

模型必须输出命题、立场、理由／叙事、发言主体、依据片段和未知原因；不支持的字段可以拒答。不存在的片段拒收，片段存在但不支持结论仍记错。模型自报置信度不是校准概率；分数、规则覆盖条件或人工升级门槛须在开发数据上选择，再看独立测试的错误与覆盖。少量标签不足以训练或校准时，明确只做已有模型适用性检验。

**首批人工安排**：

- 至少两个开发议题各取 20–40 条 pilot，每条两人独立初标；全员讨论跨议题的典型分歧，共同改进规范。独立审计集按 WP1 确定规模，规则冻结后才开放给规则开发者。分歧由未参与初标的第三人处理或保留未知。先用 10 条开发材料实测耗时，再分配各批任务。
- 留出议题的测试材料由 A/E 独立双标，B 处理分歧并保管标签；C/D 在首次预测保存后才接触适配材料并双标，负责适配且不接触测试标签。适配首批可取 20 条，作为明确的少量标注条件；测试规模单独依据评价目标预定，不能由“还剩多少标注预算”随意决定。检索审计和困难样例另记工作量，不伪装成同一随机样本。
- 24 份已有 ASR 做标题→标题+ASR 的成对语境检查，两人分别保存判断变化与原因；不把其他话题套进彩礼命题。它是便利样例，ASR 也不是完整视频真值。

**防止泄漏**：冻结规则前，规则开发者只接触开发材料。各议题的独立审计样本先按总体抽取，视频、近重复素材和作者在模型泛化评价中按任务分组；不因组间重叠或预测困难而删换审计样本。另报告与开发材料隔离的测试子集及其组成；子集不足就不声称跨作者／素材泛化。既有 200 条中先前用于调规则或定义的条目登记为开发材料；旧 40/160 拆分只说明原抽样安排，不自动证明新版测试独立。

**评价**：人工可判定率、未知原因、初始一致率和分歧；模型各标签支持数、混淆、precision/recall/F1、错误率—覆盖率及证据片段支持情况。人工也不确定的条目不强编真值；机器可判定率与在可评价条目上的准确率分报。κ 仅对固定标注者对和可定义标签报告，不把不同人混成一对。理由多标签和新理由分别检查，不由立场 F1 代替。

各议题的审计比例描述相应检索候选视频池，不是平台曝光或全部相关内容。先逐议题报告，再按明确权重汇总；不能让一个大议题掩盖其他议题失效。需要区间时说明抽样单位、有限样本及检索／系统标注误差未被覆盖。随机审计用于估计表现，优先复核高风险内容用于改善系统，两类不混算。

**输出与验收**：外部标签、分歧和预测表；`analysis/content_v2/`、`docs/analysis/content_audit_v2.md`。首批每条有原始初标和处理状态，所有模型／规则及工具调用流程有冻结版本与原始成绩；多数条目无法判断、某类为零或简单方法胜出都可以形成完整结果。按任务表现选择模型和流程，不预定复杂度或进行无必要的模型竞赛；人工金标准与模型辅助标注分开，AI 自评只作辅助。

### WP3：带证据和不确定性的曝光镜子（A 主责，B 实现统计，E 呈现）

**技术与工作**：分布统计、重复识别、固定条数／日历窗口、简单集中阈值或漂移检测、错误率与覆盖分析。无需自创“茧房总分”。输出命题下的立场、理由／叙事、引用与重复关系、时间变化、参照来源和未知。

- 候选、确认相关、可判定和缺失分别计数。对确认相关的 `R` 条中，某标签已知 `S` 条、未知 `U` 条，展示可判定子集比例及 `[S/R, (S+U)/R]`。这只是未知标签的可能范围，不是置信区间，也不包含未检索到的内容；`R=0` 时不给比例。
- 只有兼容标签和明确来源的分布才作参照；JS 用以 2 为底的定义。理由多标签先报逐项覆盖，不能把重叠比例直接塞进单标签 JS。用户历史、外部来源、明确目标和模拟供给分别命名，不默认 50:50。
- 区分“长期集中但无突变”与“最近发生变化”。统计分布不直接判伤害；显示依据并允许用户不调整。用内容 ID、文本近重复和可确认引用关系识别重复，不能把不同作者视为不同证据来源。
- 开发构造序列至少覆盖：话题多而同议题理由单一；合理的专门兴趣；长期集中／突然变化；同素材跨账号重复；稀疏与语境不足；候选池本来单边。检测目标按情境定义，不能将全部单边序列标为“有害”。

**时序验证**：先在开发序列确定窗口、最低支持数、未知容忍度、集中／变化规则及重复报警处理，再在独立整条序列上评价。构造生成参数和随机 seed 分开，不把同一滑窗的重叠片段随机拆成训练／测试。报告每条轨迹在固定观察期内至少一次误报的比例、已定义事件的检出率、发现所需曝光数和拒绝比例；稀疏导致延迟就如实报告，不用逐窗准确率掩盖反复检查的误报。

**输出**：`analysis/mirror_v2/`、`docs/reports_v2/`，至少有真实候选池报告、明确构造的对照轨迹、证据不足报告，以及随后 WP6 的仿真轨迹报告；通过 WP1 条件时另加自然个人轨迹。报告注明数据类型，错误标签更正后能够重算。

**验收**：可从输入表复算主要数字；未知没有藏进中立或分母外；相同话题分布、不同观点／理由的序列可以得到有意义的区别。无法确认时显示证据不足，不强制给分。真实内容报告不能冒充已经实现个人持续诊断。

### WP4：平台控制机制与真实负反馈关联（B 主责日志，D 主责机制）

**4a 日志分析。** 使用已固定的 `tab=1` 标准日志事件；按 `(user_id, time_ms, video_id)` 稳定排序，要求前 200／后 100 条齐全，每人按时间最多前 5 个，选中事件位置相差 >300，得到 **524 次、205 人**。不按效果重选事件。

围绕事件视频作者，计算较早 100 条 `[-200,-101]`、紧邻之前 100 条 `[-100,-1]`、之后 100 条 `[+1,+100]` 中同作者曝光比例，事件本身不入分母。记为 `a_early、a_pre、a_post`，报告三个水平、`a_post−a_pre` 和前趋势 `a_pre−a_early`。先在用户内平均事件变化，再对用户等权；按用户整组 bootstrap 1,000 次、seed=1110 给 95% 区间。这是样本不确定性，不消除混杂。

固定诊断：每人仅首事件；排除前后 100 条内其他 hate（已知剩 339 次，用户数重新报告）；前 200／后 100 条均在 72 小时内的子集；前窗作者比例为零的占比。空子集给 N/A。前 200 条中位耗时约 13.28 小时、后 100 条约 4.12 小时，因此不能换算成“几分钟见效”。同作者变化不是同观点变化，零变化也不自动说明按钮无效。

**4b 能力与机制表。** 按平台、固定版本和入口记录：作者／关键词／topic 硬过滤，预测负反馈评分，搜索、关注、个性化设置，探索／多样性；列操作输入、作用层、可执行条件、可能误删、已知证据与未知。代码阅读使用已有固定 X 快照，不靠最新网页印象替换版本。

必须保留已核实的更正：excluded-topic 硬过滤通路存在；`−47.52` 乘的是预测概率，不是点击一次扣固定分；5% 多样性遥测采样不等于 5% 推荐多样性；1,024 是相关请求表示长度，不能据此断言全部平台记忆长度。公开默认值不自动等于生产配置，DPP 的向量多样性不等于观点多样性。

**4c 文献对照。** 从已有 Kaplan、Liu、Mozilla 等原始材料整理平台／年份、处理、评价入口、分母、后续观看和结果定义；需要时补充其他已读审计。百分比不能直接排成平台强弱榜；引用已有完整方法时明确本项目复用部分。出处与访问缺口统一见来源台账。

**与仿真的关系**：源码确定可参考的通路，日志描述一个样本中的现象，文献提供独立机制与实验依据。共同用于选择需要比较的假设，而不是把 X 代码、快手结果和虚构用户拼成“已校准真实平台”。作者反馈关联不足以识别语义反馈泛化或学习速度。

**输出与验收**：`analysis/buttons_v2/`、`docs/analysis/negative_feedback_v2.md`、`docs/analysis/control_capabilities_v2.md`。样本、窗口、用户权重和诊断可复算；结果为正、负、零或互相冲突均报告；每个可执行操作有证据范围。该模块辅助主线，不替代观点测量与干预验证。

### WP5：减少、保留、补充与策略选择（E 主责流程，D 实现，C 校验）

**技术与工作**：把自然语言目标整理为对象、减少／保留／补充、例外、预算和期限；展示具体例子供确认。通过任务标签 `T/K/U` 评价，冲突与未明确指定归入 `U` 并单列。有限策略枚举、约束筛选与 Pareto 比较足够，不默认强化学习或新优化器。

**AI／Agent 的用途**：LLM 可将自然语言目标转为上述结构，由用户确认；检索 Agent 可搜索、读取并对照来源，组织缺失理由及补充材料；行动助手调用能力表与策略评价程序后解释选项。可以复用 [Qwen-Agent](https://github.com/QwenLM/Qwen-Agent) 等工具调用／检索框架，选择时检验本任务表现，不绑定框架。比例、成本、约束与 Pareto 结果由程序计算，Agent 引用实际返回值；补充主张须带可核查出处。内容标签、来源可信度与用户认可分别检验，多模型投票不当作真值。平台执行仍依赖真实接口和用户所选操作。

**先做静态比较**：不处理、整话题删除、关键词过滤、作者屏蔽、保守语义规则／选定模型，以及带保留约束和补充的方案。另列使用完备人工／构造真值的 oracle 上界，不能与实际算法混称已实现性能。候选策略可不优于简单规则。

真实样本的整话题删除是“删该议题的全部检索命中”，不是读取相关性真值后完美删除；各议题的关键词、规则和屏蔽作者的选择只用允许的开发数据。作者未出现在 audit 就报告零覆盖。静态真实样本、原创案例和动态仿真分别出表。

**信息补充是工作，不只留一个界面入口**：对纳入首轮验证的每个议题建立可追溯的补充材料目录，首批以 10–20 条检查流程，后续按理由覆盖缺口补充；记录标题／来源、适用命题、理由、证据条件和访问日期。已有材料可先用，不足时再检索公开原文；两人核对与目标的相关性和来源支持。采用关键词或现成语义检索选出候选，人工确认其是否增加了理由、只是重复、或仍有争议。留出议题的目录若用于调整规则或理由体系，须计入适配条件，不能声称零目标域开发。不能让模型生成一段“相反观点”就算补充成功；没有合适来源时显示未填补。

**约束和指标**：任务给定保留率 `ρ`、未知项删除率上限 `ε` 和预算 `B`；先筛除不可执行／违反约束的策略，再比较目标残留、相关保留、理由缺口、重复、未知删除、空缺位置、操作和额外阅读量。零分母给 N/A。真实运行用预测标签判断的约束，只是估计；用独立人工标签评价实际违反情况，不能把估计满足写成真实保证。费用权重并列展示，不用一个总分隐藏取舍。

对于 `A` 个策略、`M` 种假设、`N` 条内容，标签和索引已准备后，直接逐项评价约为 `O(AMN)`；检索和模型推理另计。动作序列先限定长度或用已有简单策略，不做无限规划。

**误差与边界检查**：先用 WP2 真实混淆及未知比例分析下游误删，样本不足时说明不能可靠估计。另在最多 80 条原创卡片上设置清楚的压力条件：`T/K` 中 0/20/40% 变成未知，剩余项中 0/10/20% 交换标签，原未知保留；每格 20 个 seed（1110–1129）。评价真值不变。它检查依赖语义标签的方法，不能解释为关键词基线性能，也不能由 F1 推导这些误差率。补做针对引用、角色和特定立场的系统性错误案例；均匀噪声不能代表所有错误。

**输出与验收**：`analysis/control_design_v2/`、补充材料目录、`docs/design/control_workflow_v2.md`。流程包括发现／核查、确认目标、预览取舍、选择行动、复查；可以用文档线框。必须展示“过滤不能创造缺失理由”“全部删掉不能算成功”“服从目标仍可能加深单边性”的实例。此处只评价有限集合；平台补量和维持效果交给 WP6，不在这里推断。

### WP6：观点层面的动态仿真（D 主责，B 配合，A 复核）

**定位：核心工作包，不是有空再做的扩展。** 它回答静态分析无法回答的部分：推荐继续更新、用户继续观看之后，策略需持续多久、保留损失怎样变化、何时重新集中，以及这些结果依赖哪些未知机制。目标是可检验的条件比较，不是复刻平台或预测真人心理。

**6a 复用与更正。** 在 `analysis/simulation_v2/` 建立新版本，保留 `analysis/pilot_sim/` 历史结果。复用 v1 的候选生成、历史状态、召回／排序、用户反应和多阶段运行结构；先做“旧实现—新假设—来源—验证方式”对照。旧 NI 权重、历史模型、话题 embedding、用户参与规则和复发设定都须逐项核查，不能只改一个参数就称已同步 X。尤其：

- 旧 `−43.2` 不能标为本次固定源码的 `−47.52`；若保留简化评分，应注明是受源码启发的模型，相关折合系数一起检查。
- FIFO、记忆容量、跳过是否入历史、NI 泛化与计数式预测均属模型假设；不称 Phoenix 复现，也不把 1,024 当真实全部记忆。
- 旧“类目多样性拟合”至多是宏观量级检查，不校准观点、信念或反馈因果机制；旧结果不直接移入 v2 结果表。
- v1 在复发阶段加入残余种子兴趣；v2 将这一机制单独设置，不能把外加兴趣变化归因于算法自行反弹。

可加入 LLM 驱动的模拟用户或行动 Agent，检查自然语言目标、复杂内容及工具选择如何影响策略；与规则型、数据驱动行为模型分别比较。其输出反映模型与提示设定，不能作为真实偏好、满意度或认知变化的测量；用于生成行为的模型不能同时充当唯一效果裁判。

**6b 状态与更新。** 给出规格、伪代码和一个可手工追踪的小实例，再实现 CPU 上的简单离散时间模型：

| 对象 | 最低表示及处理 |
|---|---|
| 内容与供给 | 话题、目标命题、立场、理由、叙事、作者／引用来源；供给可均衡或单边，允许同话题不同观点与同观点不同理由 |
| 用户自然行为 | 对内容的参与倾向、位置影响和可选的变化过程；这是行为模型，不是本人认可的目标 |
| 明确目标 | WP5 的减少／保留／补充、例外和预算，独立于参与倾向保存；用于评价和显式行动 |
| 平台状态 | 行为历史及简化偏好估计、负反馈、关注／屏蔽；更新规则和遗忘可替换 |
| 观测与控制 | 模拟真值、系统看见的文本标签及未知分开；控制器只读可获得字段，不读取隐藏真值 |
| 一步 | 召回／排序 → 记录平台曝光 → 可用的本地筛选或补充 → 用户反应与显式操作 → 更新历史 → WP3 复查 |

平台曝光、经本地过滤后可见内容和外部补充三条流分开记录。本地删去的项目是否被平台计作曝光必须作为接口假设写清楚；读了外部材料不自动改变平台历史，只有明确建模的平台内搜索、观看、关注等行为才更新相应状态。

初始默认规模拟用 5 个话题、每轮 60 个候选、展示 10 条、50 个模拟用户；正常／集中形成／干预／后续四阶段分别 20／30／50／50 步。重点议题包含不同立场、条件表达、理由及重复来源，标签只描述内容，不给各立场预设真伪等级。这些数值是便于运行的设计起点，不是数据估计；先 benchmark 再冻结。集中阶段既可由选择反馈形成，也须有供给本来单边的对照，不能只构造一种必然支持我们结论的世界。

**6c 策略。** 沿用 v1 的不行动、NI、搜索、关注、个性化设置及组合策略思想，但动作对象改为明确的观点／理由目标，保留对相关议题的兴趣。新版先比较下表四种主策略；搜索、关注和粗粒度控制再作为有明确用途的分解比较，不要求对所有按钮做全组合。

| 主策略 | 实际变化 | 必须记录的边界 |
|---|---|---|
| D0 不新增显式操作 | 按预先给定的自然行为继续观看 | 不默认“被动等待”同时意味着停止所有目标内容互动 |
| D1 单独负反馈 | 对控制器识别的目标内容反馈 | NI 按作者／话题／语义泛化分别建模，未知则暂缓 |
| D2 有保留约束的过滤与补充 | 筛除目标表达，保留相关信息，补入可追溯理由 | 若是本地过滤，只改变本地可见流；补充不假装直接改平台 |
| D3 反馈 + 定向搜索／关注 | 反馈目标内容，并在平台内寻找／关注提供所缺理由的内容来源 | 动作成本和行为写入规则明确；不能把搜索不同话题当保留原议题 |

另用静态 WP5 的粗粒度基线作至少一个动态对照，检查其保留损失与作用边界，不预定它必须失败；搜索和关注可分别运行以解释 D3。个性化关闭／恢复作为平台能力具备时的情境假设保留，不能由随机抽样日志宣称真实关闭效果。新编号不沿用旧 S0–S5 的指标定义，映射写入模型说明。

**6d 实验与统计。** 主比较固定一组公开列明的机制参数，对四种策略分别运行三类后续行为：停止显式干预且不增加旧目标内容参与；停止干预并恢复较强的旧观看；继续执行干预。每格至少 20 个独立 seed，首批 **4×3×20＝240 次运行**。同一 seed 下策略共享初始世界和可配对的随机输入；尽可能分离供给、反应、模型错误的随机流，避免分支消耗随机数造成假配对。

每个 seed 内先汇总用户，再用 seed 间的配对差异、区间和原始分布比较策略；不能把同一模拟世界的 50 个用户当成 50 次独立模型实验。运行时间与内存先记录，若超出每轮 CPU 预算，先缩减候选数／用户数或关闭非必要 DPP，保留动态循环、四主策略和独立重复。新规模冻结后统一重跑，不只缩减不利配置。

敏感性围绕需要支持的结论安排有限对照：NI 泛化范围、历史遗忘／跳过记录、探索、供给中可用理由、分类的未知／系统性错误；每次改变一个机制，并选择少量关键组合检查交互。不要做无理由的大型全因子网格。是否使用 DPP 由问题决定；若保留，明确它操作的向量是否真的区分观点。另有目标改变的案例：从改变时点使用新目标，不能把用户改变意愿叫作策略复发。敏感性比较同样保存配置和独立 seed。

**6e 成功、维持与代价。** WP0 的任务给出目标内容上限、相关信息保留要求、补充理由要求及观察期；在独立开发运行中确定评价细节，然后冻结。至少连续 3 个预先规定的评价窗同时满足要求才记为该任务下达标，阈值不是普适“健康值”。同时记录目标内容的绝对曝光和议题内部比例、相关内容的绝对保留、来源／理由覆盖、未知、空缺、操作、额外阅读与持续维护。

只有删去全部议题、增加无关内容稀释占比或把内容判成未知，均不能算逃离成功。动态保留量与相同情境的无干预参照及任务下限一起解释，不能只靠每轮过滤后比例。分别报告控制器“认为达标”与模拟真值下达标，用于观察误判传播。

在给定期限内未达标记为**未达标／右删失**，报告达标率和达到目标的曲线；不能把未达标者都赋予最后一步后计算“平均逃离时间”。复发仅对先达标者评价，同时报告条件分母和全部样本轨迹；比较不同策略时说明这些子群可能不同。模拟效用只是行为模型里的代理量，不叫真实满意度；步数不换算为分钟。

**输出与验收**：`analysis/simulation_v2/` 的规格、配置、代码、运行清单和原始汇总；`docs/analysis/dynamic_intervention_v2.md`。至少完成主比较、关键机制敏感性及一个“话题保持、观点／理由结构改变”的可检查示例。先用小实例核对状态更新、动作成本、控制器可见字段和达标判定，再运行实验。结论可为无策略稳健有效，但必须能解释对哪些假设敏感；不要求复现 v1 的数字或某策略获胜。

### WP7：跨议题检验、闭环整合与课程交付（E 主责，全员贡献）

**迁移是核心检验维度。** 在至少两个议题上共同开发并冻结流程后，应用于 WP1 锁定的完整留出议题，检查内容字段、理由目录、命题规则、参照、阈值、行动和报告哪些可复用。先仅替换事先写明的议题说明并保存预测，再向 C/D 开放首批 20 条适配样本；调整后在同一未开放标签、样本量预先确定的测试集上保存第二轮预测。A/E 和 B 按 WP2 标注、裁决并保管测试标签，不参与 C/D 的适配决策；两轮预测锁定后才汇合评价。已用于调参的测试只能作为开发结果。

分别报告各开发议题独立审计，以及留出议题零目标域标注与少量标注适配的表现、拒答、人工时间和改动清单；设计议题配置本身也有成本。测试含开发作者／近重复时按 WP2 另报隔离子集。自然候选不足或多为未知，仍交付实际覆盖、失败原因及跨议题构造检验；明确尚无该领域的充分实证，不能把构造结果写成通用性能。三个议题是起步验证结构，后续按尚未覆盖的困难增加案例，不以数量代替正确验证。

**闭环案例**：至少贯通一个“发现线索 → 回看证据 → 确认目标 → 比较策略与补充来源 → 动态复查”的实例。每一环明确哪些是真实材料、设计任务或仿真；不能编造一个仿佛真实参与者经历了全部过程的故事。没有真人也能交付可供人阅读的证据报告、取舍表和条件化操作指引。

**课程材料**：4–6 页 Plan、约 5–10 项精选来源、期中材料、最终报告、个人日志／反思、10 分钟展示和离线备份。全文围绕同一个用户问题组织，不把八个工作包写成八个独立课题。计算深度用输入输出、规则／伪代码、误差、复杂度、示例和结果体现；无需完整软件上线。

**输出与验收**：`docs/analysis/transfer_v2.md`、闭环案例、课程正式材料及“主张—证据—边界”索引。每项结论对应实际完成的验证；第一层技术结果不越级成真人认知改善。成员姓名由组内填写，不虚构。本次同步内部文档本身不等于重写或提交课程 PDF。

## 5. 可选工具与真人验证

工具承载同一用户流程，不另开“必须开发 app”的主线。最低可用载体是本地报告、notebook 或静态线框；条件允许再做个人信息流助手：导入本人授权记录、核查／更正标签、确认目标、比较行动、查看补充来源、再次导入复查。

工具只声称实际可读和可改的内容。无平台接口时提供手动操作辅助；浏览器工具不能假装控制手机 app；外部补充与平台内曝光分开。敏感历史优先本地处理，导入、删除、更正和外部模型传输须有清晰选择。

真人评价可以从理解和操作任务开始：能否指出报告依据、识别未知、纠正误判、选择满足任务约束的行动。先写评价设计，招募与同意条件具备后再实施；未进行时明确记为未完成。组员自测属于技术复核，不代表用户研究。更长期的认识变化与平台干预因果效果需要单独设计，不能附带宣称。

## 6. 资源不够或结果不理想时怎么办

| 情况 | 执行分支 | 保留的交付与结论边界 |
|---|---|---|
| 标题大量缺少语境 | 报告未知原因；用 ASR 对照定位有用补充，再判断是否需要新增材料 | 可判定性及语境价值；不强制自动判断完整视频 |
| 模型不可获得／错误较多 | 继续已可运行的规则与人工流程，保存原成绩；新模型先小批验证 | 自动化边界及下游误差分析；不许用 oracle 冒充实现 |
| 真实个人轨迹不合格 | 交付密度审计、真实内容报告、构造与动态轨迹 | 时序方法仍完成；真实个人发现速度未验证 |
| 迁移议题候选不足／几乎只有未知 | 保留已锁定样本与结果，做跨议题配置及构造检验；新增样本另版本记录 | 验证迁移条件和失败，不声称通用准确率 |
| 候选供给缺少理由 | 从独立可追溯目录补充；找不到则标记未填补 | 明确过滤的能力边界，不生成虚假“平衡” |
| 反馈关联接近零或诊断翻转 | 报告水平、变化、区间、样本组成及前趋势 | 控制层次与选择偏差；不强行拟合仿真得到同一结论 |
| 策略在一些机制下失效／复发 | 保留失败轨迹，定位泛化、记忆、供给或误判假设 | 条件化的适用范围，不把有利配置当现实结论 |
| 仿真运行过慢 | benchmark 后减小世界规模，先用简单排序，记录缩放并统一配置 | 多轮反馈、主策略、独立重复和维持评价保留 |
| 没有真人／平台接入条件 | 交付任务设计、证据报告、操作说明和小型本地演示 | 不宣称真实效果；app 和完整实验不阻塞课程交付 |

这些分支在结果出来前确定。核心研究问题、动态工作包和迁移检验不会因数据不理想就被悄悄替换为类别熵、单次过滤或界面展示。

## 7. 依赖、投入与时间线

主依赖为 **WP0 → WP1/WP2 → WP3/WP5 → WP6/WP7**。这不是完全串行：WP4 的日志与源码可立即推进；WP3 用构造序列开发；WP6 在第一周就整理旧代码和模型规格，以明确假设先运行，随后接入冻结的标签误差、目标与报告接口。不得等全部真实数据齐备后才开始仿真。

首轮投入估计如下；包含方法、有限实现和模块文字，不是已实测工时，也不是以这些数量限制 Working Plan。标注投入暂按跨议题合计约 300–500 条双标材料估算，检索审计另计；这是预算试算，正式各议题样本量由 pilot 和精度需求确定，随后重估工时并说明取舍。每周根据实际完成速度更新，优先保住研究链条和关键验证。

| D | 源码机制、有限控制实现、动态状态与更新、模型检查及敏感性 | 复核观察性关联的解释；由 B 分担运行与汇总 |
| E | 相关工作整合、意图与行动流程、补充目录组织、报告及课程材料 | 组织迁移盲测与闭环案例，复核证据类型及主张 |

全员参与开发议题的双标、各自章节和至少一次他人模块复核，按冻结后的各议题样本清单分配数量。留出阶段 A/E 双标测试集，C/D 处理首次预测后开放的适配集，B 负责裁决与标签保管。额外检索审计和语境工作另记，结合其他工作包调配投入；不能为平均标注数量破坏盲测。每周一次约 30 分钟同步，用版本化输入、结果表、解释和未解决问题交接，不只报完成百分比。

## 9. 数据与结论验收

保存来源、版本、许可、文件哈希、抽样规则、模型／提示版本、配置和 seed。大表、匿名用户 ID 与原始内容留在受控外部目录；仓库保存脚本、规范、适当去标识的必要片段、原创案例和汇总。ShortVideo 类目展开行不能重复算曝光；跨数据集类别须显式映射，不按同一数字 ID 直接拼接。

交付前逐项检查：

- 通用问题没有被写成只适用于彩礼；案例支持的范围也没有被扩大为所有议题。
- 内容理解、镜子、干预、动态复查都有设计、可检查实例和相应验证；不以模型名字或界面代替技术内容。
- 成熟方法可以直接成为最终方案；新增复杂度有实际失败和收益依据，没有为创新而创新。
- 真实内容、真实日志、源码、他人实验、构造序列、仿真与真人材料分别标注；未知与零结果完整出现。
- 自然兴趣、可见行为、用户明确目标、平台记忆和供给分开；“满足指令”“曝光改变”“认识改善”分开评价。
- 静态删掉内容不冒充平台长期改变；动态仿真是核心证据之一，但其结论带着机制、行为、误差和供给假设。
- 迁移零样本／适配结果与开发成绩分开，人工成本可追踪；自然数据不足就收窄性能主张。
- 理想 I1–I7 中已做、可部分验证和仍缺失的能力逐项更新；没有 app 或真人研究不妨碍清楚报告已有成果。
- 课程 PDF、Word、演示与内部计划的版本状态一致；未生成或未提交的材料不标成已完成。

完成标准是：**围绕一个具体而可跨议题复用的用户问题，将发现、理解、干预和复查做成一条有数据、有计算、有动态检验、能说明适用条件与代价的解决路径。**
